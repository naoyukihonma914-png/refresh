# 実装メモ

## 段階1（土台）— 2026-10-31

仕様書 10.2 の段階1だけを実装した。段階2以降の生成ボタン・購入・自動カーソルの描画・ガイド・各世界・リリースは未実装。過去の試作のコードは流用していない。

### できたこと

- `game/` に TypeScript・Vite・React の新しい実装を作成した。
- `systems/state.ts`：版番号つきの保存可能な単一データ。所持資源、生成の累計、保存解禁の状態、自動生成の台数、性能7項目、時刻を持つ。将来の世界のデータは、その世界を実装する段階で追加する。
- `config/balance.ts`：この段階で必要な世界1の仮値と性能7項目の段階・値段・効き目を一元化。世界1の項目名は `tools/economy_sim.py` の `CONFIG.w1` と対応させた。未使用の世界2以降の数値は、各段階で追加する。
- `content/script.ts`：画面の文面を集約。ガイドと要望の台本は、それぞれの段階でここに追加する。
- `systems/save.ts`：保存解禁前の書き込み禁止、内容の検査、主データと正常な前世代1つの予備保存、予備からの復元、両方破損した場合の確認待ち、保存領域を使えない場合の通知。JSONの入出力と初期化の処理も用意した。
- `systems/time.ts`・`economy.ts`：100ms刻みの時間処理、経過時間の端数保持、既存の仮値による自動生成量の計算、不在分の100%加算とストレージ上限、時刻が戻った場合の0扱い。手動生成と購入の処理はまだない。
- `systems/runtime.ts`：10秒ごとの保存、変更直後・タブ復帰・画面を離れるときの保存。非表示中とスリープ後の経過を不在として処理する。復帰後に時刻を保存し、同じ不在分を再び受け取らない。
- `systems/tab.ts`：後から開いたタブの操作を停止。Web Locks を基本とし、使えない場合は期限つきの保存領域のリースを使う。所有権を失ったタブは保存前にも停止する。
- `components/Stage.tsx`：1920×1080を縦横比を保って中央に表示。拡大にも対応し、縦長・1280×720未満では案内を1行表示する。余白は現在の画面と同じ白。
- `?debug=1` の小窓で、資源追加・保存解禁済み状態・性能変更・ファイル入出力・2回確認の初期化を試せる。通常画面には出ない。
- `npm run build` で `game/dist/index.html` 1つにJSとCSSをまとめる。現段階では画像や外部書体を使わず、外部通信の処理もない。
- Pagesのワークフローを更新。見本は従来どおりルートに残し、ビルドを `/play/` に配置する。今回はローカルのコミットまでで、push・公開は行っていない。

- `cd game && npm run build`：TypeScriptの検査とViteのビルドが成功。出力は `index.html` のみ（約242kB）。外部スクリプト・CSS・画像の参照がないことも検査した。

- 破損した主データからの予備復元、両方破損した場合の停止、確認を取り消した場合に元データが残ること、新規開始の承認後だけ初期化されることを確認した。

### 見本との違い

段階1の通常画面は、目標・ピクセル・保存状況のみ。見本01の生成ボタン、区切り線、作れるものの箇条書きは段階2のため置いていない。保存状況の行が見本より上にあり、所持数は新規開始の0である。押せない仮のゲーム操作は置いていない。

見本のHTMLは横幅だけで縮小するが、実装は仕様書5.1を優先し、縦横両方に収まる等倍率で拡大・縮小して中央に置いた。

### 仮に決めたこと

| どこで | 何を | 仮の判断 |
|---|---|---|
| `state.ts`・`save.ts` | 保存形式と既存の試作 | 新しい形式を第1版とする。実在する旧版ができたら版ごとの変換を登録する。参考資料のセーブは推測で変換しない。未対応形式は元データを残して確認待ちにする |
| `save.ts` | 保存領域のキーと予備の扱い | `refresh.save` と `refresh.save.backup` を使用。保存時に正常な主データだけを予備に回す。壊れた主データで予備を上書きしない |
| `runtime.ts` | ブラウザの処理停止の判定 | 前回の計算から1秒を超えて処理が止まった区間は、不在と同じ上限で扱う。値は `balance.ts` に置いた |
| `time.ts` | 時計が過去に戻った後 | 時刻の基準を過去に戻さず、元の時刻に追いつくまでは加算しない。負の時間で減らしたり、同じ時間を再加算したりしない |
| `runtime.ts`・確認用画面 | ごく短い復帰の知らせ | 1秒未満または1ピクセル未満は通知を表示しない。計算自体には加算する。「0分・+0」の知らせを避け、1分未満は秒で表示する。世界ごとの最終的な通知は後の段階で実装する |
| 開発用小窓 | データの入出力と初期化の置き場所 | 各世界の設定画面ができるまでは `?debug=1` でのみ操作する。通常画面に仮の設定ボタンを加えない |
| `fixtures.ts` | 決まった状態への入口 | `foundation-start`、`foundation-saved`、`foundation-offline-capped` の3つ。実セーブを読まず、メモリだけに保存する。世界を飛ぶ操作は、その世界の実装時に追加する |
| `Foundation.tsx` | 土台を確認する画面 | 見本01の文書の体裁を使い、操作のない最小表示にする。生成・購入・動きは段階2で作る |

### 再確認の入口

`game/` で `npm run dev` を実行し、表示されたURLに次を付ける。

- `?debug=1`：通常の保存領域で土台を確認（操作で実セーブが変わる）。
- `?state=foundation-start`：新規状態。
- `?state=foundation-saved&debug=1`：保存解禁・自動生成を試す。実セーブには影響しない。
- `?state=foundation-offline-capped`：上限を超える不在からの再開。実セーブには影響しない。

自動のブラウザ確認は `tools/check_foundation.py`。PythonのPlaywrightとインストール済みChromiumを使う。Pagesのワークフローと同じ配置（見本がルート、ゲームが `/play/`）をHTTPで配信したうえで、`python tools/check_foundation.py --base-url <配信元URL>` で実行する。画像と検査結果はGit管理外の `game/artifacts/stage1/` に出力する。
