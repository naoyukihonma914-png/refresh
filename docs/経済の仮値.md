## 1. 3つの資源
| 資源 | 何に使う | どう増える | リリースで |
|---|---|---|---|
| ピクセル | 画面の中身を作る（部品・アプリ・自動カーソル） | 世界ごとに違うやり方（下記）。全世界で1つの財布 | なくなる |
| トークン | スキルツリー（各世界の「設定」「拡張機能」） | やり遂げたときにまとまって入る（アイコンや部品の書き出し、要望メール） | 残る |
| ドル | スペック（画面の性能） | リリースの売上 | 残る |

- トークンは全世界で共通の1つの財布（企画メモ4章の提案をこの案の前提にしている）

## 2. 遊ぶ人の想定（計算に使った数）
- 素の画面で押し続ける速さ：1秒に2.5回
- 組木で下絵のマスに置く速さ：1秒に1.5マス（「左右対称」で×1.8、「塗りつぶし」で×1.4）
- 何かを作るたびに迷う時間：4秒、ガイドの言葉を読む時間：1回15秒
- デスクトップでは、半分の時間は手を動かし（画面を撮る・要望に応える）、半分は眺めているだけ

## 3. 素の画面
| 作るもの | ピクセル | 効き目 |
|---|---|---|
| 枠線 | 10 | 1回のクリックが +1 → +2 |
| 保存 | 40 | 自動保存が始まる。ここから自動カーソルが買える |
| 自動カーソル | 15（1台ごとに×1.15） | 1台が1秒に0.5回押す（30Hzのとき） |
| 色 | 200 | 自動カーソルが×1.5の速さに |
| 書体 | 700 | 1回のクリックが×2 |
| 配置 | 2,000 | 「作れるもの」が2つ先まで見える |
| 動き | 4,500 | 連打の「勢い」：続けて押すと最大×1.6（平均×1.3ほど） |
| 組木を作る | 12,000 | 世界2へ |

- 押した1回のピクセル ＝（1＋枠線の1）×書体の2 ×色深度の倍率
- 自動カーソル1台 ＝ 押した1回のピクセル × 毎秒0.5回 × 色の1.5 × リフレッシュレートの倍率（30Hz＝1、60Hz＝2）

## 4. 組木
| 作るもの | ピクセル | 効き目 |
|---|---|---|
| 選択ツール | 4,000 | ホーム画面の部品の見た目を変えられる |
| ボタン（部品） | 9,000 | 自動カーソルの押し先が増え、ホーム画面の生成が×1.5 |
| 拡張機能（スキルツリー） | 15,000 | トークンが使えるようになる |
| スイッチ（部品） | 20,000 | 集中モード：ドットのピクセル×2、その間は自動生成が止まる |
| スライダー（部品） | 32,000 | 自動生成の間隔を長くするほどまとめて入る（最大×1.2） |
| 入力欄（部品） | 45,000 | 書き出しに名前を付けられる（ガイドが名前を聞く） |
| 窓の枠（部品） | 65,000 | 練習用の下絵が開く |
| タスクバー（部品） | 90,000 | デスクトップの組み立てに必要 |
| デスクトップとして組み立てる | 200,000 | 256色が必要。世界3へ |

- **ドット1つ** ＝ 10 ピクセル × 色深度の倍率
- **アイコン1つ**（16×16）＝ 下絵のマス150。描き上げて書き出すとトークン1（解像度が上がるとマスもトークンも増える）
- **名前つきの下絵は1つずつ届く**（追加の提案）：フォルダ（最初から）→ ごみ箱（ボタンの後）→ 時計（スイッチの後）→ メール（スライダーの後）→ 写真（入力欄の後）→ 設定（窓の枠の後）。トークンが一度に溢れないようにするため
- **練習用の下絵**（追加の提案）：窓の枠の後に開く。描けばピクセルになるがトークンは出ない。手を動かしたい人の稼ぎ先
- **部品を作って書き出す**とトークン1（ボタン・スイッチ・スライダー・入力欄・窓の枠・タスクバー）

## 5. デスクトップ
### 作るもの（アプリ）
| アプリ | ピクセル | 効き目 |
|---|---|---|
| ファイル | 30万 | 書き出したもの・スクリーンショットが並ぶ |
| メール | 60万 | 要望の一覧。同時に3件まで溜まる |
| 持ち場 | 100万 | 自動カーソルを窓にドラッグして働かせられる |
| 写真 | 500万 | 現像と壁紙。持ち場にもなる |
| ごみ箱 | 1,500万 | リサイクル（平均すると生成×1.05ほど） |
| 時計 | 4,000万 | 予約：席を外していても「画面を撮る」が半分の割合で働く |
| テーマ | 1億 | 見た目だけ |
| ターミナル | 2.5億 | 自動化：「画面を撮る」を毎回自動で行うなど |
| 配信ソフト | ― | 60Hzが必要。v1.0 のリリースへ |

### アプリの小さな機能（決定：間延びを防ぐため、各アプリに2〜3個）
アプリの合間に、ピクセルで買える小さな機能を挟む。買うとその窓に**実際に使える操作が1つ増える**。写る部品が2つ増えるので「画面を撮る」が少し得になり、持ち場になるアプリ（ファイル・写真）ならその窓のカーソルの働きが×1.25。

| 順 | 機能 | ピクセル | 窓の変化 |
|---|---|---|---|
| ファイルの後 | ファイル：並べ替え | 45万 | 名前・日時・種類の見出しを押すと並び替わる |
| メールの後 | メール：返信の下書き | 80万 | 要望を開くと、直す場所を開くボタンが付く |
| 持ち場の後 | ファイル：検索 | 200万 | 上部の検索欄で絞り込める |
| 〃 | ファイル：大きいアイコン表示 | 350万 | 一覧と大きいアイコン表示を切り替えられる（描いたアイコンが大きく見える） |
| 写真の後 | 写真：切り抜き | 800万 | 壁紙にする範囲を選べる |
| 〃 | 写真：比べて見る | 1,100万 | 現像の前後を左右に並べて見比べる |
| ごみ箱の後 | ごみ箱：元に戻す | 2,200万 | 捨てたものを戻せる |
| 〃 | メール：フォルダ分け | 3,000万 | 済んだ要望を「対応済み」に分けられる |
| 時計の後 | 時計：タイマー | 5,500万 | 時間を決めて「画面を撮る」を予約 |
| 〃 | 時計：カレンダー | 7,500万 | リリースした日や作った日が記録される |
| テーマの後 | テーマ：壁紙のスライドショー | 1.4億 | 選んだ壁紙が時間で切り替わる |
| 〃 | テーマ：アイコンの大きさ | 1.9億 | デスクトップのアイコンの大きさを変えられる |

- ターミナルの機能（命令の追加など）は、v1.0 の条件がそろった後の伸びしろとして後で決める

### 持ち場（自動カーソルが働く窓）
| 窓 | カーソル1台の毎秒 | 1台目の値段（1台ごとに×1.15） |
|---|---|---|
| 組木（アイコンを描く） | 40 | 3万 |
| ファイル（整理） | 150 | 15万 |
| 写真（現像） | 700 | 150万 |
| ターミナル（処理を回す） | 6,000 | 4,000万 |

- 同時に持ち場にできる窓の数：メモリ 4GB で3つ（1周目）。それより多くの窓があるときは、どこで働かせるか選ぶ
- **アプリの更新**（何度でも）：その窓のカーソルの働きが×2。値段は「1台目の値段×15」から始まり、更新ごとに×6。画面上は「写真 1.2 → 1.3」のようにアプリの版が上がる
- 素の画面の自動カーソルも、組木の窓の中のホーム画面で押し続ける

### 画面を撮る
- 1回で ＝ いまの毎秒生成 × 写っている部品の数 × 0.5秒ぶん
- 写っている部品の数 ＝ 開いている窓・アイコン・タスクバーの部品など（目安 10〜60）
- 撮ったあとの待ち時間：30秒（スペックの「描画性能」で短くなる）

### 要望メール
- 4分に1件届く（スペックの「通信速度」で早くなる）。応えるとトークン2。溜まるのは3件まで

## 6. スキルツリーの値段（トークン）
- 1周目帯：1〜4（例：塗りつぶし2、左右対称3、レイヤー一覧1、スポイト1、キーボードで押す1、更新履歴1、窓を半分に並べる2、通知から直す2、スクショの連写4）
- 2周目帯：10〜30（例：構成を引き継ぐ12、持ち場を増やす15）
- 3周目以降帯：50〜
- 計算では、チュートリアルで約12トークン（1周目帯を7つほど）、v1 全体で約110トークン入る。2周目帯は v1 の後半から少しずつ取れる

## 7. リリースの売上（ドル）
売上 ＝ 25 ×（この周に生んだピクセルの合計 ÷ 1万）の 0.4乗 ×（1 ＋ 0.05 × 作ったものの数）
- 「作ったものの数」＝ 作った部品・アプリ ＋ 書き出したアイコン。たくさん作り込むほど売れる（企画メモの「完成度にも連動」）
- 0.4乗なので、ピクセルを10倍貯めても売上は約2.5倍。粘りすぎより、区切りよく出す方が得になりやすい
- 計算の結果：v0.1 は 約300ドル、v1.0 は 約14,500ドル

## 8. スペック
| スペック | 段階と値段（ドル） | 数字の効き目 | 見た目の変化 |

| 解像度 | 低 → 中 1,500 → 高 20,000 → 超高 300,000 | アイコンのマス 16×16 → 32×32 → 64×64 → 128×128（マスもトークンも増える）、画面を撮る ×1.25ずつ | 文字・線・アイコンの精細さ |
| リフレッシュレート | 30Hz → 60Hz 5,000 → 120Hz 60,000 → 240Hz 700,000 | 自動処理の速さ ×1 → ×2 → ×4 → ×8 | カーソルや窓の動きの滑らかさ |
| メモリ | 4GB → 8GB 800 → 16GB 8,000 → 32GB 90,000 → 64GB 1,000,000 | 持ち場にできる窓 3 → 4 → 5 → 6 → 8 | 同時に開ける窓の数 |
| ストレージ | 128GB → 256GB 100 → 512GB 2,000 → 1TB 25,000 → 2TB 300,000 | 放置で貯められる時間 2時間 → 4 → 8 → 12 → 24時間 | ファイルの保存領域の表示 |
| 通信速度 | 低 → 中 3,000 → 高 40,000 | 要望メールの間隔 4分 → 3分 → 2分 | ― |
| 描画性能 | 低 → 中 6,000 → 高 80,000 → 最高 900,000 | 画面を撮る待ち時間 30秒 → 20 → 12 → 8秒 | 影・半透明・切り替えの演出が増える |

## 9. 放置と不在
- 開いたまま眺めている間：自動カーソル・持ち場・ホーム画面の生成は100%進む
- 閉じている間（不在）：同じく100%で進むが、ストレージの時間（最初は2時間、v0.1 の売上の残りで4時間）まで（**決定**）。画面を撮る・要望に応えるは進まない（要望は3件まで溜まる）
- 戻ったとき：不在の間に増えた量を、その世界らしい形で1回だけ知らせる（例：デスクトップなら通知、素の画面なら1行の文章）

## 10. 計算の結果（`tools/economy_sim.py`）
| 区間 | 目標 | 計算 |
|---|---|---|
| 素の画面（1周目） | 約15分 | 10分（＋ガイドを読む時間） |
| 組木（1周目）→ 256色で止まる | 約40分の時点 | 41分 |
| v0.1 リリース → 素の画面を作り直して組木へ | 約60分の時点 | 53分 |
| v1：素の画面と組木の作り直し | 約1時間 | 43分 |
| v1：デスクトップ（ターミナルまで） | 残り | 6時間03分 |
| v1 の合計 | 約7時間 | 6時間46分 |

- 実際の人は迷ったり寄り道したりするので、計算より少し長くなる見込み。目標の範囲には入っている
- デスクトップで新しいものが増える間隔：約10〜30分（アプリの小さな機能を足す前は約1時間あいていた）

## 11. 確認したこと（2026-10-30）
1. **デスクトップの後半の間延び**：**決定**。各アプリにピクセルで買える小さな機能を2〜3個ずつ足す（5章の表）
2. **不在の上限**：**決定**。最初は2時間、ストレージ 256GB（100ドル）で4時間。v0.1 の売上の残りで買える
