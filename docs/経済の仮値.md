## 2. 遊ぶ人の想定（計算に使った数）

## 3. 素の画面

| 枠線 | 10 | 1回のクリックが +1 → +2 |
| 保存 | 40 | 自動保存が始まる。ここから自動カーソルが買える |
| 自動カーソル | 15（1台ごとに×1.15） | 1台が1秒に0.5回押す（30Hzのとき） |
| 色 | 200 | 自動カーソルが×1.5の速さに |
| 書体 | 700 | 1回のクリックが×2 |
| 配置 | 2,000 | 「作れるもの」が2つ先まで見える |
| 動き | 4,500 | 連打の「勢い」：続けて押すと最大×1.6（平均×1.3ほど） |
| 帯（上と下） | 6,500【仮】 | アプリ名・ピクセル表示と情報の帯（外形の土台）。数値は第3版で追加した新項目のため未計測 |
| 作業台まわり | 9,000【仮】 | 作業台・部品パネル・道具の列（制作の土台）。同上 |

- 完成した部品は、それぞれ小さい毎秒の値を持つ（第3版の統一モデル。値は調整フェーズで部品ごとに置く）【仮】

- 押した1回のピクセル ＝（1＋枠線の1）×書体の2 ×色深度の倍率
- 自動カーソル1台 ＝ 押した1回のピクセル × 毎秒0.5回 × 色の1.5 × リフレッシュレートの倍率（30Hz＝1、60Hz＝2）

## 4. 工房（第3版で全面書き直し）
部品はUIセット単位で購入し（購入＝作る権利と材料。完成品は付かない）、4工程で制作する。内訳は付録A 2章。

| 買うもの（セット） | ピクセル【仮】 | 備考 |
|---|---|---|
| 共通部品セット（5部品） | 4,000 | 窓の枠・スクロールバー・基本ボタン・見出しの帯・進み具合のバー |
| 土台セット（6部品） | 30,000 | タスクバー・デスクトップの地・アイコンの置き場・通知・壁紙の表示面・作れるものの小窓 |
| ファイルセット（6部品・必須） | 65,000 | 一覧・戻る・並べ替え・検索欄・大きいアイコン表示・保存領域の表示 |
| メールセット（5部品・必須） | 90,000 | 一覧・本文の欄・返信の下書き・フォルダ分け・未読の印 |
| デスクトップとして組み立てる | 200,000 | 必須セットの完成が条件。256色が必要。世界3へ |

- 任意セット（写真・ごみ箱・時計・テーマ・ターミナル・タスクマネージャー）の値段は、有用さに応じて別途置く（時計は安く、ターミナルは世界3の規模）【仮】
- **工程払い**：1工程ごとに、部品の区分ごとの定額【仮】（大きさでは変わらない）。完成でまとまった額＋部品そのもの
- **完成した部品**は、部品ごとの毎秒の値を持つ【仮】（統一モデル。仕様書 3.3）
- **部品をエクスポート**するとトークン1
- 旧版の「ドット1つ」「アイコンの下絵」の計算は廃止（第3版）

### 持ち場（自動カーソルが働く窓）
| 窓 | カーソル1台の毎秒 | 1台目の値段（1台ごとに×1.15） |
|---|---|---|
| エディタ（制作の補助） | 40 | 3万 |
| ファイル（整理） | 150 | 15万 |
| 写真（現像） | 700 | 150万 |
| ターミナル（処理を回す） | 6,000 | 4,000万 |

- 同時に持ち場にできる窓の数：メモリ 4GB で3つ（1周目）。それより多くの窓があるときは、どこで働かせるか選ぶ
- **アプリの更新**（何度でも）：その窓のカーソルの働きが×2。値段は「1台目の値段×15」から始まり、更新ごとに×6。画面上は「写真 1.2 → 1.3」のようにアプリの版が上がる
- 素の画面の自動カーソルも、エディタの上部の生成ボタンを押し続ける

### 画面を撮る（第3版：補助的な稼ぎ）
- 1回で ＝ 写っている部品の数 × 1部品あたりの小さな単価【仮】（主軸の稼ぎにはしない。単価は調整フェーズで置く）
- 写っている部品の数 ＝ 実際に見えている窓・部品だけを数える（隠れた部品は数えない。仕様書 4.3）
- 撮ったあとの待ち時間：30秒（スペックの「描画性能」で短くなる）

### 要望メール
- 4分に1件届く（スペックの「通信速度」で早くなる）。応えるとトークン2。溜まるのは3件まで

## 6. スキルツリーの値段（トークン）
- 1周目帯：1〜4（例：一括で置く2、寸法を数値で入れる3、レイヤー一覧1、スポイト1、キーボードで押す1、更新履歴1、窓を半分に並べる2、通知から直す2、スクショの連写4）
- 2周目帯：10〜30（例：構成を引き継ぐ12、持ち場を増やす15）
- 3周目以降帯：50〜
- 計算では、チュートリアルで約12トークン（1周目帯を7つほど）、v1 全体で約110トークン入る。2周目帯は v1 の後半から少しずつ取れる

## 7. リリースの売上（ドル）
売上 ＝ 25 ×（この周に生んだピクセルの合計 ÷ 1万）の 0.4乗 ×（1 ＋ 0.05 × 作ったものの数）
- 「作ったものの数」＝ 作った部品・アプリ・完成したセット。たくさん作り込むほど売れる（企画メモの「完成度にも連動」）
- 0.4乗なので、ピクセルを10倍貯めても売上は約2.5倍。粘りすぎより、区切りよく出す方が得になりやすい
- 計算の結果：v0.1 は 約300ドル、v1.0 は 約26,000ドル（2026-10-31、長く遊べる仕組みを入れ、値段の並びをなめらかにして再計算）

## 9. 放置と不在
- 開いたまま眺めている間：自動カーソル・持ち場・完成した部品とツールの生成は100%進む
- 閉じている間（不在）：同じく100%で進むが、ストレージの時間（最初は2時間、v0.1 の売上の残りで4時間）まで（**決定**）。画面を撮る・要望に応えるは進まない（要望は3件まで溜まる）
- 戻ったとき：不在の間に増えた量を、その世界らしい形で1回だけ知らせる（例：デスクトップなら通知、素の画面なら1行の文章）

## 10.5 長く遊べる仕組みの数値（2026-10-31 追加・仮値）
- **実績**：1つ取るごとに全生成 +1%（足し算。この区間で取れるのは約25個）
- **前の世界の積み上げ倍率**（デスクトップのジョブに掛かる）：エクスポートしたアイコン1つごとに +0.5%（50個まで）、素の画面のオートカーソル1台ごとに +0.1%
- 上の2つを入れると v1 が約1時間半速くなったため、デスクトップの後半（写真以降）の値段を3倍にして約7時間に戻した。新しいものが増える間隔は約6〜33分
- **受託案件の報酬**：永続で全生成 +5%（1件ごと）と、特別な壁紙・テーマ
- **出来事**：素の画面「取り残されたピクセル」＝毎秒生成の20秒分、Tessera「ずれ直し」＝30秒分、デスクトップ「応答なし」の再起動＝60秒分

## 12. 最後のフェーズ（v5 / 世界7）までの見通し（仮・2026-10-31）
計算：`tools/economy_macro.py`。世界4〜7の中身はまだ決まっていないので、「どの世界も、入ったときの毎秒を基準にした、世界3と同じ形の値段の並び」と仮定した大まかな見通し。世界4〜7の中身を決めたら、世界ごとの細かい計算に置き換える。

### 時間の作り方（考え方）
- 数字（値段・毎秒・売上）は指数関数的に大きくなる。**時間はそうしない**：1つ買うまでの待ち時間は「最初は約10分、世界の終わりに向けて30分前後」へ少しずつ伸び、新しい倍率が手に入るたびに一度短くなる（推定時間の「60分 → 30分」の瞬間）。1周の長さも「約1 → 7 → 9 → 10 → 11 → 13時間」と、ゆるやかに伸びる
- 値段の並び：各世界の最初のアップグレードは「入ったときの毎秒 × 約10分ぶん」。序盤は1つごとに約1.25倍、後半は約1.6倍で上がる（世界3で確かめた形）
- 新しい世界1つで、毎秒は約1,000倍になる。リリースで性能を買うと、作り直した後の毎秒が約3倍になる

## 11. 確認したこと（2026-10-30）
1. **デスクトップの後半の間延び**：**決定**。各アプリにピクセルで買える小さな機能を2〜3個ずつ足す（5章の表）
2. **不在の上限**：**決定**。最初は2時間、ストレージ 256GB（60ドル）で4時間。v0.1 の売上の残りで買える
