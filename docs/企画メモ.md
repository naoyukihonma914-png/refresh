## 0. 一言で（決定・2026-10-31）
**「ボタン1つの画面を、自分の手で “なんでも作れるパソコン” に育てて、出荷していくゲーム」**
- 作っているのは、OS・ソフト・アプリのどれか1つではなく「いま見ている画面そのもの」。版を重ねるごとに使う人の輪が広がる（自分 → 利用者 → 視聴者 → ネットの人々 → 映像を見る人 → プレイヤー）
- 製品には、最初のリリースのときにプレイヤーが名前を付ける（決定）。以後は「（その名前） v1.0」「同 v2.0」と、同じ製品の版が上がっていく
- リリースのたびに一から作り直す理由（決定）：出荷した版はお客さんのものになり、次の版は上げた性能に合わせて一から組み直す。台本⑩で伝える
- 長い目標（決定）：制作ノートの最後に「いつかは、この画面ひとつで、何でも作れるようにしたい。」を置き、全体の向かう先を最初に見せる
- 次の世界へ進む理由（決定）：性能の壁だけでなく、各リリースのあとに利用者の声をもとに榎本が次の版のテーマを提案する（v1.0 デスクトップ → v2.0 配信 → v3.0 ウェブ → v4.0 映像 → v5.0 ゲーム）。出荷の画面に次の1つだけ出す。仕様書 4.6
- ピクセルの理由づけ（決定）：これ以上は説明しない。「画面はピクセルでできている」（制作ノート）が理由のすべてで、画面はもともとピクセルの集まりなので、集めるほど画面が豊かになるのは自然。説明を重ねるとかえって理屈っぽくなる

## 1. 狙い（決定）
- 最初から最後まで「UIを作る」インクリメンタル。作ったものが、いま操作している画面そのものを変える
- 世界が色づき、精細に、豪華になっていく気持ちよさを最後まで続ける。節目では「ガラッと新しい世界」に入る
- **画面の変化を常に楽しんでもらうことが、このゲームの大きな売り**（ユーザー・2026-10-31）。どのフェーズも、古い姿から最新の姿まで、配置・大きさ・色・素材がはっきり変わる段を重ねて進化する。1周目から進化を体験させ、2周目以降も途中のフェーズに新しい進化を用意する。忘れないこと
- **PC画面の中で完結**するのが大元。物理ディスプレイや机などの外には出ない
- 各画面は本物のPCと錯覚するリアルさで、その道のプロが使うような画面にする
- 資源・生成・購入も画面の中に組み込む（外付けのゲーム用サイドバーを置かない）
- 特定OSを識別できる要素（左上の三色ボタン、ロゴなど）は使わない
- 全編を白基調にしない。色だけでなく構図・密度・素材・文字・動きで世界の違いを出す
- 写真などの画像は装飾にすぎないので、新しく作り込まなくてよい（主役はUI）
- **画像の方針**（決定・2026-10-31 ユーザー）：ゲームで使う写真などの画像は、必要になったときにGPT側（Codex など）がぴったりの画像を作る。気に入らなければ、ユーザーが著作権フリーの画像を見つけて入れることもある。既存の作品・ロゴ・他社の画像はそのまま使わない
- PC向け（ブラウザ、将来Steam）。基準の言語は日本語で、多言語に対応する（決定・2026-10-30）

## 2. ユーザーの最初の要望（大枠。改変してよいと明言されている）
- ピクセルは画面ごとに独自の方法で生成する。クリックは最初だけが主役
- スキルツリーで新しいギミックを解放する。解放には別通貨（仮：トークン）
- 各画面で、ピクセルとトークンをそれぞれ別のやり方で生む
- 転生を採用し、転生で別通貨（仮：ドル）を得る。ドルで「スペック」を上げ、各画面の数値を底上げ
- 最後まで難なく進むには、転生とスキルツリーを前提にした難易度
- スキルツリーは、生成を便利にするもの・お遊び要素・画面を充実させる要素
- 各画面のUIは大体さわれるようにし、飾りばかりにしない
- さわれるUIやギミックは、通貨に関係しない寄り道・遊びでもよい。待ち時間に飽きさせない工夫を精一杯

## 3. 決まったこと
### 転生とスペック（決定）
- **転生＝リリース**：作り上げた画面を製品として出荷し、売上がドルになる
- **スペック＝画面の性能そのもの**：解像度（線や文字の細かさ）、色深度（モノクロ → 16色 → 256色 → フルカラー → HDR）、リフレッシュレート（動きの滑らかさ・自動処理の速さ）、メモリ（同時に開ける窓・自動処理の数）、ストレージ（放置で貯められる時間）など。数値の底上げと同時に、見た目も良くなる
- 1周の中では購入で画面の「構成」を作り、周回をまたいでスペックで「描画の品質」が上がる。2周目は同じ世界がより精細・色豊か・滑らかに見える

### 時間（決定・目安）
- 最後まで約50時間（放置込み）。伸びしろは多いほどよい
- 転生は「1周じっくり」を数回（参考：Upload Labs）
- エンディングは今は考えない

### スキルツリー（決定）
- 転生しても残る
- **画面（世界）ごとにツリーを持つ**。1周目で取れる安いものから、2周目以降を前提にした重いものまで並べる。1周目でも段階的に良くでき、2周目以降の伸びしろも残す
- 各画面は最初は簡潔にし、プロの道具らしい機能はスキルツリーで段階的に増やす。最終的な操作の数は多くなってよい

### 画面設計の原則（決定）
- プロの画面らしさは保ちつつ、最初はボタンや文字を多くしすぎない。何をすればいいか一目で分かること
- さわれない飾りのUIは出さない。要素を減らすことで簡潔にする
- 見本での反映（Claude提案）：1画面の主役の操作は1〜2個／未解放のものは「次の1つ」だけ見せる／道具やパネルは手に入れた分だけ増える
- 最初に作った情報量の多いデザインツールの見本は、「組木のスキルツリーを全部取った姿」として活かせる（提案）

その後に決まった細部（2026-10-30。世界の並び自体は変わっていない）：
- 入るためのスペックの段階：3＝色深度 256色、4＝リフレッシュレート 60Hz、5＝通信速度「高」、6＝描画性能「高」、7＝描画性能「最高」＋メモリ 32GB
- 2 組木：見た目は古いドット絵の道具から始まり、スキルツリー「道具を新調する」で現代の道具に変わる
- 3 デスクトップ：今のWindowsを基本にした見た目
- 4〜7：現代のかっこいい見た目にする（古い見た目にしない）。中身の詳細は、Codexが最初の区間を作っている間に詰める（2026-10-31 追記：下の「どのフェーズも最終的には最新の現代感へ」により、各世界とも簡素な姿から始まり、スキルツリーで最新の姿まで進化する）
- 並びの確認（2026-10-31）：デスクトップ → 配信 → ウェブの順のまま（決定）。理由は見る人の輪の広がり（視聴者 → ネットの人々）、配信の録画がサイトに埋め込まれて始まる流れ、明暗と忙しさが交互になること
- 5 ウェブ（決定・2026-10-31）：中心は「自分のサイトを組む」。他のサイトを巡るのは脇役。ウェブは伸びしろの大きい題材なので、見た目の変化と機能の充実を特に作りこむ（ユーザーの方針）
  - 育ち方の軸は「サイトの種類が変わっていく」（自己紹介の1ページ → 作品集 → 日記 → お店 → 会員の集まる場所 → 道具として使えるサイト）（決定・2026-10-31）
  - 作りこみの3つの柱（サイトそのものが育つ／訪問者がカーソルとして見える／ネットが広がる）と、性能による見た目の変化を、方向として了承（2026-10-31）。細部は `docs/世界4-7の案.md`（案の段階）。見本はその世界を詰めるときに作る（ユーザーの指示）

並びの理由：
- 「自分のUIを使う人」が1つずつ増える（自分 → 自分のPC → 視聴者 → ネットの人々 → 映像を見る人 → プレイヤー）。スケールの上がり方を管理画面の拡大ではなく観客の広がりで出す
- 前の世界が本物のPCで起きる形で次に収まる（アプリ→窓／デスクトップ→配信の画面キャプチャ／配信→動画サイトに埋め込み／サイトの録画→映像の素材／映像や部品→ゲームのUIや場面の中の看板・映像）
- 明暗が交互に入れ替わり、並べるだけで世界の違いが分かる
- どの世界も「UIを作る」主題（配信の重ね表示、サイトのデザイン、UIや宣伝の動き、ゲームのタイトル画面やHUD）
- 操作の種類が毎回変わる（クリック → 描く → 任せる → リアルタイムに反応 → 組んでたどる → 時間軸 → 遊んで試す）
- 後半ほどリリースとつながる（ウェブのストアで作品が並ぶ、宣伝映像の出来が売上に効く、ゲームが最大の製品）

前半の詳細：
- 素の画面：最初に目標の1行「この画面を作り上げて、v1.0 としてリリースする」を表示（決定）
- 組木：最初の道具はアイコンエディタ（ドット絵）。素の画面の「ピクセルを1つ生成する」が1ドットずつ置く鉛筆になり、置いたドットの数だけピクセルが増える。1周目は解像度が低いのでアイコンはドット絵、スペックが上がると精細に描き直されていく（決定）
- デスクトップ：組木で設計した部品が本物のOSとして動く。写真現像は写真アプリとして（現像した写真を壁紙に）、テーマ／アイコンのデザインも自分の環境を作る遊びとして入れる（提案）

外した候補：
- 仮想マシン：単独の世界にすると管理画面寄りになるので、後半の自動化機能に（前の世界を仮想マシンとして裏で動かし続けて稼がせる）（提案）
- 3Dはゲームスタジオの中の具体的なビューとして出す。元ゲームの抽象的な3D空間とは別物（提案）
- 予備：スマホアプリ（エミュレーターの縦長画面でアプリのUIを作る）を、世界を増やすときの候補に

### 世界1〜3の中身（決定・2026-10-30 Claude案を全体採用）
詳細の正本は `docs/世界1-3の案.md`。要点：
- 素の画面：枠線 → 保存 → 自動カーソル → 色（1周目は16色）→ 書体 → 配置 → 動き → 組木を作る。トークンはまだ出ない
- 組木：主役は「ドットを描く」と「書き出す」。下絵のマスに置いたドットだけピクセルになる（自由に描くのは寄り道の「自由帳」）。書き出し（アイコン・部品）でトークン。作った部品はホーム画面に新しい操作として増える（例：スイッチ＝集中モード）。出口「デスクトップとして組み立てる」は256色が必要で、1周目はここで止まり試作版 v0.1 のリリースへ
- デスクトップ：主役は「画面を撮る」と「要望メールに応える」（トークン）。自動カーソルは窓にドラッグして持ち場を決める（同時に働ける数＝メモリ）。出口の配信ソフトは60Hzが必要で、v1.0 のリリースへ
- 前の世界が次の世界の材料になる（素の画面→組木のホーム画面.ui、描いたアイコン→デスクトップのアイコン、部品→窓やタスクバー、組木の色や角の丸み→デスクトップの見た目）
- スキルツリーの見せ方：素の画面＝素朴な設定ページ、組木＝「拡張機能」、デスクトップ＝「設定」アプリ。各世界とも 1周目帯／2周目帯／3周目以降帯 × 便利／充実／遊び
- 1周目のスペックの見え方：16色、アイコン16×16、30Hz、デスクトップの写真壁紙は256色でざらつく

### 経済の仮値とスペック（2026-10-30 ユーザーが案どおり了承。数値は仮値）
正本は `docs/経済の仮値.md`、確認用の計算は `tools/economy_sim.py`。要点：
- 資源：ピクセル（全世界で1つ。リリースでなくなる）／トークン（全世界で1つ。残る）／ドル（残る）
- リリースの売上 ＝ 25 ×（周回のピクセル合計÷1万）の0.4乗 ×（1＋0.05×作ったものの数）。計算では v0.1 約300ドル、v1.0 約14,500ドル
- スペック7項目：色深度・解像度・リフレッシュレート・メモリ・ストレージ・通信速度・描画性能。表示要件は 世界3＝256色、4＝60Hz、5＝通信速度「高」、6＝描画性能「高」、7＝描画性能「最高」＋メモリ32GB
- 計算の結果：チュートリアル約53分、v1 約6時間46分（目標どおり）
- 決定：デスクトップの各アプリに、ピクセルで買える小さな機能を2〜3個ずつ足す（新しいものが増える間隔を10〜30分に）
- 決定：不在中も100%で進むが上限あり。最初は2時間、ストレージ 256GB（60ドル。2026-10-31に100ドルから変更）で4時間

### 製品ページとスクリーンショットの意味（ユーザー案・2026-11-01。方向は採用、細部は未決定）
- リリースの流れを「リリースする → 製品（製品ページ）ができる → お客さんが買う → 結果とドル」にする。出荷するときに、お客さんが見る製品ページを表示し、その後に売上（ドル）の画面へ進む
- 製品ページはリリース（フェーズ・版）ごとに違う。v0.1 は小さな試作版のページ、v1.0 はデスクトップ製品のページ…と、版が進むほど立派になる（ページの見た目もその時代に合わせて進化させる：Claudeの提案）
- スクリーンショットを撮る理由をはっきりさせる：①進み具合のアルバムに残す ②製品ページに載せる。撮った画像から、製品ページに載せるものを選ぶ
- 決定（2026-11-01）：ページに載せた画像の出来（写っている部品の多さ・種類、窓の配置のきれいさ）が売上に少し効く（最大+10%など【仮】）。
- 決定（2026-11-01 ユーザー）：オリジナリティを出せる幅を持たせる。ペイントソフトは指示（フィードバック・テンプレート）以外にもいろいろなテンプレートを用意し、自由にも描けるようにする。スクリーンショットにも自分らしさを出せる幅を持たせる（Claudeの案：壁紙・テーマ・自作アイコン・窓の並べ方・写す窓の選び方。評価は「正解との一致」ではなく、多さ・種類・整い方で見て、個性を罰しない）。
- 以前のClaudeの提案の残り（確認待ち）：フィードバックをくれた利用者が、お客さんのレビューとしてページに登場する。スクリーンショットのピクセルの稼ぎは残す（デスクトップの稼ぎ方のため）
- 製品ページの段（2026-11-01、ユーザーが示した手本の画像から作成。確認待ち）：①低い版＝フリーソフト紹介サイト風（見本05-1）→ ②中間1＝ソフトウェアの保管庫サイト風（05-2）→ ③中間2＝ゲーム配信ストア風（05-3）→ ④最終＝アプリストア風（05-4）。サイト名・ロゴは使わず架空の名前（ソフト広場／ソフトウェア書庫／ハコ／余白ストア）。版との対応（2026-11-01 ユーザー案）：各リリースの「最後のフェーズ」に合わせて、版ごとに1つずつ違うページを作るのもよい（例：ゲームの世界の版にはゲームストア風）。v0.1＝①ソフト紹介サイト、v1.0＝②ソフトウェア書庫は決定（2026-11-01、仕様書4.6）。残りはClaudeの対応案（確認待ち・世界4〜7の中身が決まってから確定）：v2.0（配信）＝④アプリストア、v3.0（ウェブ）＝ウェブサービスの紹介ページ（新規・手本待ち）、v4.0（映像）＝動画サイトの作品ページ（新規・手本待ち）、v5.0（ゲーム）＝③ゲームストア。ゲームストア風のレビュー欄はユーザーが示した画面を手本に作成（見本05-3b）

### アプリは「作って入れる」（決定・2026-11-01 ユーザー）
- デスクトップの基本アプリ（ファイル・メール・写真 など）は、ピクセルで買って導入して終わりではなく、自分で作って入れる（「UIを作る」というコンセプトのため）
- Claudeの案（確認待ち）：アップグレードで手に入るのは「アプリのひな型」（中身が空の窓）。ペイントソフトの「組む」の場面で、自分で作ったパーツ（一覧・ボタン・タブ・入力欄・スライダー など）を窓に置いて組み立てる。置いたパーツに応じてアプリの機能が働く（例：ファイルは一覧を置くと中身が見え、並べ替えのボタンを置くと並べ替えられる）。組んだ配置がそのままアプリの画面になる。アプリごとに必要なパーツが少しずつ違い、新しいアプリが新しいパーツを作る理由になる
- 決定（2026-11-01 ユーザー）：アプリの中のUIの配置・色などのデザインもプレイヤーに任せ、好みにできるようにする
  - 見本 03-6（ファイルのアプリを組む場面）を作成し、この形で決定（2026-11-01）。入れる時期は段階6.5の前（段階6.2。ユーザー決定）
  - 決定（2026-11-01 ユーザー）：後からでもアプリの作りを変えられるようにする。作りの自由さによるUI同士の干渉・詰み・不具合を防ぐことに気を付ける → 仕様書4.9「詰みと不具合の防止」
  - Claudeの案（確認待ち）：使える色の数は色深度のスペックに従う（16色・256色…。性能を上げると選べる色が増える）。素材の見た目は時代に従う（95風なら灰色の立体）。デザインが苦手な人のために「おすすめの配置」で一度に組める。整った配置は撮影の配置ボーナスに効くが、色や好みの配置そのものは損得に関係させない
- 作る量についての考え方（Claudeの整理・2026-11-01）：同じ時代の中では、窓・ボタン・一覧などの「素材の見た目」を全アプリで共有する（95風なら全アプリが灰色の立体）。世界（フェーズ）どうしは、構造と遊び方から別物にする（配信・ウェブ・映像・ゲームは見た目の付け替えにしない）。アプリの配置は自分で組むので、同じ時代でもアプリごとに違う画面になる。時代ごとに「顔」になる部品（95のスタートの位置のボタン、7のガラス など）は作り込む

### ホーム画面のパーツの見直し（2026-11-01）
- 決定（ユーザー）：ホーム画面（素の画面）に置く「スイッチ（フォーカスモード）」「スライダー（間隔）」はいらない。選ぶ意味が薄く、飾りに近い操作だったため
