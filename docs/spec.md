## 1. 狙いと判断基準

### 1.1 一番の楽しさ
最初から最後まで「UIを作る」インクリメンタルゲーム。**作ったものが、いま操作している画面そのものを変える**。生成ボタン1つの素っ気ない画面から始まり、画面が色づき、精細に、豪華になっていく。節目では「ガラッと新しい世界」に入り、前の世界はその中の部品として収まる。

**画面の変化を常に楽しませることが最大の売り**（決定・2026-10-31）。どの世界も古い姿から最新の姿まで、配置・大きさ・色・素材がはっきり変わる段を重ねて進化する（4.8）。1周目から少なくとも1回の大きな見た目の進化を体験させる。

### 1.2 必ず守ること
1. **PC画面の中で完結**する。物理ディスプレイ、モニターの枠、机、部屋は描かない
2. **画面全体がゲーム世界**。資源の表示・生成・購入は、その世界の画面の中に組み込む。外付けのゲーム用サイドバーや、世界を小さな枠に展示する構成にしない
3. 各画面は**本物のPCソフトと錯覚するリアルさ**で、プロの道具らしく。ただし最初は簡潔にし、機能は解放順どおりに増やす
4. **さわれない飾りのUIを置かない**。画面にあるボタンは押せて、意味のある反応をする。1画面の主役の操作は1〜2個。作っている最中の部品も、作りながら実際に操作できる（押せるボタン、動くスライダー）こと
5. **未解放のものは「次の1つ」だけ**見せる。道具やパネルは手に入れた分だけ増える
6. **特定OSを識別できる要素を使わない**（左上の赤黄緑の三色ボタン、既存OSのロゴ、それに似た四角4つのマークなど）
7. **全編を白基調にしない**。世界ごとに配色・構図・密度・文字・動きを変える
8. **小さな英単語、意味のない数字、雰囲気だけの短いコピーを散らさない**。画面の文字はすべて選んだ言語（基準は日本語。10.4）で、そのソフトに実際に必要な文言だけ。選んだ言語の中に別の言語の単語を混ぜない
9. ゲームの仕組みの用語（転生、プレステージ、周回など）は画面に出さない。物語の中の言葉（リリース、性能、売上、バージョン）で表す
10. **お手本はあるが、従い方は評価しない**（決定・2026-11-03。2026-11-02 の「正しい置き方を示唆しない」を置き換える。「お手本」は制作を助ける仕組みの呼び名で、人物のガイド（4.5）とは別）。初回プレイはお手本ONが標準で、お手本に沿えば速く・気持ちよく進める（4.2「お手本と制作の二層」）。ただし配置の整い具合や、標準からの変え幅そのものを損得にしないのは従来どおりで、お手本に従うことを数字のうえで優遇せず、外しても損をさせない。お手本が与えるのは速度と気持ちよさだけ。評価するのは「何を作ったか」「何が写っているか」などの中身だけ

### 1.3 避けること（不採用の理由つき一覧は12章）
- 管理画面のパネル数が増えるだけの成長
- 色数や発光を増やすだけの「豪華さ」
- 説明用の大きな窓で画面を覆うチュートリアル
- 文字や数字を詰め込み、大事な部分と飾りの区別がつかない画面
- 課題をなぞらせるだけの作業（下絵をなぞって描く等）。お手本（4.2）は当てはめる気持ちよさのための足場に留め、いつでも離れて自分の設計にできること

### 1.4 迷ったときの判断基準（優先順）
1. その操作の結果、画面が目に見えて変わるか
2. 本物のソフトにその表示・操作があっても不自然でないか
3. 初めて見た人が、次に何をすればよいか一目で分かるか
4. 数値の調整で済むことを、仕組みの追加で解決していないか

## 3. 基本ループと経済

### 3.1 資源
| 資源 | 用途 | 増え方 | リリースで | 表示場所 |
|---|---|---|---|---|
| ピクセル | 画面の中身を作る（部品・アプリ・自動カーソル） | 世界ごとに違う（3.3） | 0に戻る | 世界1：本文の1行／世界2：上部バー／世界3：タスクバー |
| トークン | スキルツリーの項目を取る | やり遂げたときにまとまって（エクスポート・要望メール） | 残る | 世界2：上部バー（初めて手に入れた後）／世界3：タスクバー |
| ドル | スペックを買う | リリースの売上 | 残る | リリースの画面のみ |

- ピクセルとトークンは、それぞれ全世界で1つの財布
- ドルとスペックは、リリースの画面の中だけで扱う（ふだんの画面には出さない）

### 3.2 ループ
- **1周の中**：ピクセルを生む → 作れるものを作る → 画面が変わり、生む手段が増える（増幅）→ 次の世界へ
- **トークン**：エクスポート・要望でまとまって入る → スキルツリーで、そのアプリを便利・充実・楽しくする（残る）
- **リリース**：表示要件の壁に当たる → 条件をそろえてリリース → 売上でスペックを買う → 新しいバージョンを最初から（速く、きれいに）作り直す
- **選択の場面**：自動カーソルを買うか次の作るものを待つか／持ち場をどの窓にするか（メモリの数まで）／スキルツリーの取る順番／リリースする時期（売上は伸びるが逓減する）／どのスペックを先に上げるか

### 3.3 数値と式
**すべて付録C（`docs/経済の仮値.md`）の値を使う**。経済の文法は全世界で1つに統一する（決定・2026-11-02）：

- **作ったもの個々が、自分の「毎秒ピクセル」の値を持つ**。「個数 × 一律の単価」にはしない。世界1・2では作ったUI（部品）が、世界3では作ったツール（アプリ）が生産者になる。世界3のアプリの毎秒は、そのアプリを構成する部品の毎秒の合計（＋アプリの更新の倍率）で決まる
- **制作の工程でもピクセルが入る**（即時報酬として小さく）。完成した部品は上の毎秒の源になる。世界4の部品を世界3で作る場合など、完成品が本稼働するのが先の世界でも、作っている間の稼ぎは工程が担う
- 主な式：
- 素の画面の1回のクリック ＝（1 ＋ 枠線なら1）× 書体なら2 × 色深度の倍率 ×（動きの勢い 1.0〜1.6）
- 自動カーソル1台 ＝ 1回のクリック（勢いなし）× 毎秒0.5回 × 色を作っていれば1.5 × リフレッシュレートの倍率
- 部品の制作（1工程）＝ 部品の区分ごとの定額（大きさでは変わらない。大きさは純粋にデザインの選択）
- 持ち場のカーソル1台 ＝ その窓の基本値 × 2^(アプリの更新回数) × 1.25^(そのアプリに組んだ機能部品の数) × 色深度 × リフレッシュレートの倍率
- 画面を撮る ＝ 写っている部品の数 × 1部品あたりの小さな単価（補助的な稼ぎ。主軸にはしない）
- 売上（ドル）＝ 25 ×（この周に生んだピクセルの合計 ÷ 1万）^0.4 ×（1 ＋ 0.05 × 作ったものの数）
- 値上がりする買い物：自動カーソル ×1.15／台、持ち場のカーソル ×1.15／台、アプリの更新 ×6／回
- 倍率の層（実績、前の世界の積み上げ、色深度など）は、個々の生産者の合計への調整として掛ける

**実装上の約束**：
- 数値はすべて `game/src/config/balance.ts`（1か所）にまとめる。コードの中に値段や倍率を直接書かない
- 付録Eの計算と同じ値を使い、設定ファイルを変えたら付録Eも直せるように、項目名を対応させる（付録E の `CONFIG` と同じ構造が望ましい）
- 大きな数の表示（言語ごとに切り替える。10.4）：日本語は、所持数を3桁区切り（例 836,240）、1億以上は「1.23億」、値段は「80万」「2.5億」のように万・億で短く。英語などは 836,240／1.23B／800K／250M。中国語は万・亿、韓国語は 만・억。区切りの記号（, と.）も言語の習慣に従う
- **最後までの数の大きさ**（2026-10-31）：v5 では10の24乗ほどになる（付録C 12章）。日本語は 万・億・兆・京・垓・𥝱 の単位を使う（兆より上も「1.23京」のように）。英語は K・M・B・T の後は Qa・Qi・Sx。各世界の設定画面で「指数で表示（1.23e18）」に切り替えられる。単位と表示の切り替えは1か所の関数にまとめる

### 3.4 スペック（付録C 8章）
| スペック | 段階 | 数字の効き目 | 見た目の効き目（必ず実装） |
|---|---|---|---|
| 色深度 | 16色 → 256色 → フルカラー → HDR | 全ピクセル倍率 | 16色：世界1の「色」が16色の固定パレットに限られる。部品の色の選択も16色のパレット。256色：写真（壁紙・写真アプリの中・スクリーンショットに写る写真をすべて）を減色表示（各色6段階）。フルカラー：減色なし。写真は最終的に最新の綺麗さになる（12.2） |
| 解像度 | 低 → 中 → 高 → 超高 | 作業台の格子の細かさ（作れる部品の最小の寸法と位置の刻み）。画面を撮る ×1.25ずつ | 文字・線・部品の精細さ。写真の粗さも変わる（12.2） |
| リフレッシュレート | 30Hz → 60Hz → 120Hz → 240Hz | 自動処理 ×1/×2/×4/×8 | 自動カーソルと窓の動きのコマ数：30Hz＝毎秒15コマ、60Hz＝30コマ、120Hz＝60コマ、240Hz＝制限なし（違いが分かるよう誇張した演出） |
| メモリ | 4GB → 8 → 16 → 32 → 64GB | 持ち場にできる窓 3/4/5/6/8 | ― |

### 4.2 世界2 工房（エディタ）
見本：。入った直後はさらに簡素（5.3）。

**入る演出**：世界1の最後の部品（書き出す）がはまり、画面がエディタとして起動する（約1.2秒）。世界1の画面がどこかへ縮むのではない。作ってきた画面そのものが、道具として目覚める

**この世界の仕事**
- 世界3のアプリの部品（パーツ）を、アプリごとの組（UIセット）単位で制作する。ここで作った部品が、世界3で実際にアプリになる
- 部品は、行き先のアプリの窓の中で・実際の大きさで作る（作業台。後述）。作った部品はそのまま実際に操作できる（ボタンは押せる、スライダーは動く）。飾りの死んだUIは作らない（1.2）

**UIセットと購入の仕組み（決定・2026-11-02）**
- 部品はアプリごとのUIセットにまとまる：共通部品セット（全アプリ共通の基礎）、デスクトップ画面セット（窓まわり・タスクバーなど、デスクトップ画面そのものの部品）、ファイルセット、メールセット、写真セット、ごみ箱セット、時計セット、テーマセット、ターミナルセット、タスクマネージャーセット（全46部品。スクロールバーは独立した部品にせず窓の枠に一体化する。内訳は付録A 2章）
- セットは**ピクセルで購入**する。購入で手に入るのは「そのセットを作る権利と材料」であって、完成品ではない。作るのはプレイヤーの仕事
- **必須セット**（世界3へ進む条件）：ファイルセット、メールセットの2つ。世界の土台（共通部品・デスクトップ画面）は本線の進行で作る
- **任意セット**は、世界2でも世界3でも作れる。値段は有用さで決める：飾りに近いもの（時計など）は安く世界2からいつでも作れるものにし、便利なもの（ターミナルなど）は世界3の稼ぎの規模の値段にする
- 完成したセットは、世界3のファイルの中に書類として格納される（4.3）。世界3で、必須のUIを作ってファイルに格納することが、世界4へ進む条件の1つになる

**制作のしかた：殻＋ピースをはめる（決定・2026-11-03。旧4工程は廃止）**
- 部品を選ぶと、その部品の土台（**殻**）が行き先の窓の中に・実際の大きさで現れる。殻が部品の居場所と大きさを決める（場所と大きさを決める工程はない）。殻には、要素（**ピース**）をはめる窪みが見えている
- **パネルの構成（決定・2026-11-03）**：右のパーツパネルは、階層を行き来して表示が入れ替わる方式（ドリルダウン）にしない。**場所を分けて常時置く**：上部に分類タブ（共有パーツ／必須ツール／任意ツール。対応は、共有＝共通部品セット、必須＝デスクトップ画面・ファイル・メール、任意＝写真・ごみ箱・時計・テーマ・ターミナル・タスクマネージャー・プラグイン・配信）、その下にセットの選択ゾーン、さらにその下に選んだセットのパーツの選択ゾーン。制作中はパーツのゾーンの下に、そのパーツのピースの一覧が続く。「いまセットを見ているのかパーツを見ているのか」を読まなくても場所で分かることが目的
- **押せるものの判別**：ボタンや行は、パネルの面と同じ色で同化させない。押せるものは浮き出しと状態の色で示し、選択中は枠で囲わず、**同じゾーンの他の行を暗くして**示す。押せないものは沈み込み＋灰文字で明確にする（デザインの決まりにも追記）
- 制作中のパネルに並ぶピースの一覧は状態表示のみ。ピース名を押すと、そのピースが作業台の端に出現する。ドラッグして窪みの近くで離すと吸着し、「カチッ」という音と軽い反応ではまる。**はめたピースはその場で実際に働く**（ボタンは押せる、スライダーは動く）。はめたピースは置き場へドラッグで戻して外せる
- **完成＝全ピースがはまった時点**。「仕上げ」の関門はない（試す行為は、はめたピースが実働することで自然に果たされる）。完成でまとまったピクセルと、部品そのものが手に入る
- ピースをはめるごとに小さいピクセルが入る（ピース払い。旧工程払いの総額をピース数で割る。初回は均等割り）。完成した部品は毎秒の源になる（3.3）
- **窪みは部品の構造そのもの**（窓枠にボタンの座があるのは実物通り）。お手本のオン・オフで窪みは消えない（4.2「お手本と制作の二層」）
- **窪みの色**：未装着の窪みは、はめるピースの色では塗らず、**灰色系の「まだ入っていない」色**で描く（最小化などのボタンの窪み、タイトル帯の窪みも同じ）。ピースと同じ色で塗ると、はまっているのか窪みなのか見分けがつかないため。はめた後にピースの色になる。世界1のはめ込みも同じ
- **窓のボタンの色**：最小化・最大化・閉じるのボタンは、タイトル帯の色とは独立に**灰色の面＋記号**で描く（帯の色と被って溶けないように）
- **ドラッグ中のピースの大きさ**：ピースはドラッグ中も**窪みと完全に同じ大きさ**で表示する。持ち上げで拡大しない（大きさが窪みとの対応の手がかりになる、パズルとしての約束）
- **同寸のピースは窪みを共有する**：最小化・最大化・閉じるは同じ大きさで、どの窪みにもはまる。機能は位置ではなくピース（記号）に従う——右端に最小化をはめたら、右端のボタンが最小化として働く。並び順は「どの窪みに何をはめたか」で決まり、調整では変えない
- 状態が対になるピース（未読／既読、実行／停止）は、1つの座に2ピースを重ねてはめ、切り替えで表に出る方が替わる
- スクロールバーは独立したピースにせず、**窓の枠の右端の窪みに1ピースとしてはめる**（溝・つまみ・矢印は一体。色・太さ・矢印の有無は枠の調整で決める）
- 部品ごとの殻・ピース・窪みの対応は `docs/世界2-殻とピース対応表.md` を正とする
- **調整（こだわり）**：色・角の丸み・文字の大きさ・影などは、制作の必須工程ではない。作る途中でも完成後でも「調整を開く」からいつでも開いて変更できる（数値の入力欄は開いたときだけ出す）。標準から変えた分には「オリジナリティ」として小さい評価が付く（変えない選択も同じだけ尊重される規模に留める）。段③（Gesso）以降は、押し心地・重ねたときの反応・スライダーの滑りなどの「動き」も調整の選択肢に加わる
- 制作に失敗はない（「放っておいても損はない」原則）。行き詰まりの防止は4.9と同じ（窓の内側だけ、読めない色の組み合わせ不可）
- 完成した部品は、いつでも**エクスポート**できる（トークン。4.2「書き出す」）

**お手本と制作の二層（決定・2026-11-03）**
- **初回プレイはお手本ONが標準**（入り切りは各世界の設定画面に置き、いつでも切り替えられる。2周目以降は前回の設定を引き継ぐ）。狙いは、考え込む前にテンポよく「カチッ」と当てはめて進む気持ちよさを用意し、凝りたい人だけが自由制作に潜れるようにすること（1.2-10）
- お手本が有効なとき：「短期目標」が常時示されるのに加え、次にはめるピースの誘導が出る。お手本が無効なときは誘導とヒントだけが消え、窪みは部品の構造として残る。調整は「おまかせ」でお手本の値を一括適用して即座に進めることもできる。**必須の意思決定はゼロ**で、すべて標準のまま完成まで進める
- **二層構造**：本線は「組み立て」（速さと爽快感）。色・形・配置の調整は「こだわり」として、作る途中でも完成後でもいつでも開いて変更できる。お手本の途中で値や配置を変えた部品は、そのまま自由制作として続く（切り替えに損得はない）
- **数字はお手本で変えない**：お手本準拠・非準拠で工程払いや部品の毎秒の値は変えない。お手本への一致度のような評価も置かない（1.2-10）。自由側の評価は、調整の「オリジナリティ」の小さい評価だけ
- **完成の気持ちよさ**：部品の完成時に、その部品の毎秒の値が合計の表示へ飛び、数字が増える見せ方をする。短い間隔で完成が続くときは、ピース払いに小さい連続ボーナス（コンボ。倍率は仮値）を付ける。達成の節目（セット完成→アプリの出現→毎秒の跳ね上がり）が数分おきに届く間隔を、解放順と価格の側で保つ

**作業台（キャンバス）**
- 部品の行き先のアプリの窓を、実際の大きさで中央に開き、その中で作る。格子の目と吸い付き、寸法の数値表示。小さい部品のために拡大表示（ズーム）がある
- 上の段のエディタでは、より細かい道具が使える（格子の細かさは解像度のスペックにも連動。3.4）

**共通部品の自由（決定・2026-11-02）**
- 共通部品（窓の枠セット・基本ボタン・見出しの帯・進み具合のバー）は全アプリの土台なので、自由度を高くする：
- 窓の枠：記号（最小化・最大化・閉じる）の**色**、記号の形、タイトル帯の色と文字の位置。並び順・左右の位置は、どの窪みにどのピースをはめたかで決まる（「制作のしかた」）。スクロールバーは枠の右端に1ピースではめる要素として一体化し、色、太さ、矢印の有無は枠の調整で決める
- 基本ボタン：形（角の丸み）、色、文字の大きさ、影（各アプリのボタンの標準の型になる）
- 見出しの帯：色、文字の大きさ、区切り線の有無
- 進み具合のバー：塗りの色、形（高さ・丸み）、帯状か滑らかか、パーセント表示の有無
- 素材感（立体・ガラス・フラット）はデスクトップの時代の段に従い、ここでは変えない（時代の同一性を保つ）

**書き出す（エクスポート）**
- 上部右の「書き出す」。作り上げた部品があるときだけ押せる
- 書き出すとトークン（部品1つにつき1）。上部バーにトークンの表示が初めて現れる
- 書き出したものは世界3のファイルに実際に並ぶ

**エディタ自身のカスタマイズ（決定・2026-11-02）**
- 変えられる：パネルの付け替え（パレット／道具の列／パーツの一覧／情報の帯を左右・上下へ）とパネルの幅、強調色、作業台の背景色、グリッドの表示と間隔、パネルの文字の大きさ。操作はドラッグでの付け替え＋設定欄（エディタが自分自身を編集する形）
- 段で決まる（変えられない）：どのパネルが存在するか（レイヤーの帯は段2から、タブ式パネルは段3から）、素材感・質感（時代の同一性）、使える道具の種類
- 下限：作業台は消せない・最小の大きさがある。パネルを画面外や重ねて隠す置き方はできない。［標準に戻す］を常備
- 自由は段と進行で増える（世界1の原則と同じ）。段1では色と帯の位置くらいから始まり、上の段でパネルの付け替え等が開く

**作れるもの（工房）**
- 左の部品パネル下部に「次に作れる」として、次の1つだけ。最下部に出口のカード「デスクトップとして組み立てる」（必要ピクセルと進み具合のバー）
- 解放順と値段：付録A 2章・付録C 4章

**出口**：「デスクトップとして組み立てる」。必須セット（ファイル・メール）が完成すると押せる状態になるが、色深度が足りないと表示要件で止まる（1周目はここで v0.1 の準備へ）

**拡張機能（スキルツリー）**：4.4

**保存対象**：作ったもの、購入したセット、部品ごとの制作状態（工程の進み・寸法・設定値）、エクスポート済みの一覧、エディタのカスタマイズ

### 4.3 世界3 デスクトップ
見本：付録D `03-0-desktop-earliest.html`（最初の姿・90年代半ば風。v1でデスクトップに来て約45分の様子）。大型アップデートで `03-1-desktop-2000s.html` → `03-2-desktop-glass.html` の姿に変わる（4.8。その先の 03-3〜03-5 は次の区間）。主役（作れるもの・ジョブ・要望）はどの段でも見つけやすい場所に置き、タスクバー・資源の出し方・通知の形は段ごとに変わる。

**入る演出**：エディタの画面が縮んで窓になり、写真の壁紙のデスクトップに置かれる。下からタスクバーがせり上がり、完成したセットのアプリが並ぶ（約2秒）

**最初の状態**：壁紙（海岸）、エディタの窓、タスクバー（エディタの窓のボタンと、ピクセル・トークンの表示だけ）、デスクトップのアイコン（エディタ・制作ノート.txt）。時計・検索欄・OSのマークは置かない

**この世界の稼ぎ（決定・2026-11-02）**
- 主軸は「作ったツールの数」：デスクトップに入れたアプリ個々が毎秒の値を持ち、その値はアプリを構成する部品の毎秒の合計で決まる（3.3）。世界を充実させる（任意セットを作る・アプリを増やす・更新する）ほど土台が育つ
- もう1つの主軸は制作そのもの：世界3の任意セットの制作と、**2周目以降は世界4の必須セットの制作**が、工程のピクセルを生む。世界4は2周目（v2）から開くので、1周目の世界3は配信ソフトの表示要件（60Hz）で止まる
- スクリーンショットは補助的な稼ぎに留める（後述）。要望メールはトークンの源（従来どおり）

**設定アプリ**：タスクバーのトークンの表示を押すと開く（デスクトップにアイコンは置かない）。中身はスキルツリー（4.4）、データ（9章）、スペックの一覧（見るだけ。買うのはリリースの画面）

**窓の操作（本物らしさの土台）**
- タイトルの帯をドラッグで移動、右上の記号で最小化・最大化・閉じる、押すと前面へ。閉じた窓はタスクバーかデスクトップのアイコンから開き直す
- 位置・大きさ・重なり順・最小化を保存する
- 「窓を半分に並べる」（スキルツリー）を取ると、画面の左右の端へドラッグで半分に並ぶ

**作れるもの（デスクトップ）**
- タスクバーのピクセル表示を押すと上に開く小窓。いま作れる1つと、その次の1つ（薄く）だけ。値段は「80万 で作る」
- ここに並ぶのは、アプリのひな型（4.9）とUIセット（4.2）。作ったアプリはタスクバーとデスクトップに並び、アイコンは架空の標準の図柄（描く仕組みはない）

**アプリを作って入れる**：4.9。ひな型に、世界2（またはここ）で作った部品を組んで入れる

**画面を撮る（補助）**
- 上部中央の帯。「画面を撮る」「写っている部品 26」「約 +2.7万」、撮るボタン
- ふだんは画面の一番上の中央に小さなつまみだけを出す。つまみを押すと帯が下へ引き出され、撮る・帯の外を押す・もう一度つまみを押すと戻る。帯がアプリのメニューや上部の帯に重なって文字を隠さないこと（2026-11-01 決定）
- 押すと画面全体が一瞬白く光り、シャッターの動き。ピクセルが少し入り、「スクリーンショット」フォルダに1枚増える
- **数えるのは、実際に写っている部品だけ**（決定・2026-11-02）：後ろに隠れた窓の部品は写らないので数えない。配置の整い具合は損得に関係させない（1.2-10）
- 写っている部品の数 ＝ 10（壁紙・タスクバーなど）＋ 見えている窓ごとに 3 ＋ その窓で見えている機能部品の数 ＋ デスクトップのアイコンの数 ＋ 表示中の通知 1
- 撮った後は待ち時間（描画性能）。撮るボタンの周りが円で減っていく
- スクリーンショットの画像は、**その瞬間の画面の状態（開いている窓・位置・壁紙・テーマ）を記録し、同じ部品で縮小して描き直す**（画像を実際に撮影しなくてよい）。保存する枚数はストレージに応じて上限（128GB で50枚、段階ごとに倍）。超えたら古いものから消えるのではなく、撮る前に「保存領域がいっぱいです」と出す（ごみ箱で減らせる）
- スクリーンショットの役割（決定）：①進み具合のアルバム ②製品ページに載せる写真の素材 ③撮影のお題・要望の対象。繰り返し撮って稼ぐ手段にはしない（似た写真ばかり溜まり、見返しづらく飽きるため）

**持ち場（自動カーソルに仕事を任せる）**
- 「持ち場」を作ると、窓のタイトルの帯にカーソルの置き場（小さな枠）が出る。自動カーソルをタスクバーの「自動カーソル」からドラッグして窓に入れる
- 持ち場にできる窓：エディタ（制作の補助）、ファイル（整理）、写真（現像）、ターミナル（処理を回す）。同時に持ち場にできる窓の数はメモリで決まる
- 窓の中でカーソルが実際に働く様子が見える：エディタなら作業台で部品の工程を進める、ファイルなら行を選んで並べ替える、写真ならスライダーを動かす、ターミナルなら文字が流れる。表示するカーソルは窓ごとに最大5、それ以上は台数を添える
- 持ち場のカーソルは窓ごとに買い足す（値上がり）。最小化した窓でも働く
- **アプリの更新**：持ち場の窓の右上に「更新」。押すとアプリの版が上がり（「写真 1.2 → 1.3」）、その窓のカーソルの働きが×2

- ファイル：完成したセットの書類（この周のもの・旧バージョンの書類）、ホーム画面にあたる制作物、スクリーンショット、**制作ノート.txt（最初から入っている。制作対象ではない）** が実際に並ぶ。開くと中身が見られる（スクリーンショットは縮小した画面）。保存領域の表示（ストレージ）。機能部品：並べ替え／検索／大きいアイコン表示

- エディタ：世界2の道具が窓として残る。世界3のUIとエディタ自身のカスタマイズ、2周目以降は世界4の部品の制作を、ここから続ける
- 配信ソフト：作れるものの最後に表示要件「60Hz以上（いまは30Hz）」で並ぶ（1周目では押せない）

**寄り道**：写真の現像と壁紙、デスクトップのアイコンを好きに並べる（ドラッグ。位置を保存）、制作ノート

**保存対象**：作ったアプリと機能、窓の状態、デスクトップのアイコンの位置、持ち場（窓ごとのカーソル数・更新回数）、要望（届いている・完了した）、スクリーンショットの記録、壁紙、テーマ、ターミナルの命令、制作ノートの本文、タイマーの予約、完成したセットと旧バージョンの書類

### 4.6 リリース
**条件と進み具合の表示**
- どの世界にも、その世界の上部（工房）またはタスクバー（デスクトップ）に「v1.0 リリースまで 2/5」の丸い進み具合。素の画面では本文の目標の行に「（2/5）」を添えるだけ
- 押すと条件一覧（済みにはチェック）。すべてそろうと「リリースする」ボタンが現れる
- v0.1 の条件：エディタを完成させる（世界2に入る）／部品を3つ作る／部品を1つエクスポートする
- v1.0 の条件：アプリを6つ動かす／要望に10件応える／必須セット（ファイル・メール）を含むセットを4つ完成させる／壁紙を自分で決める（写真から壁紙にする）／ターミナルで自動化を1つ動かす
- v0.1 の条件は、工房の出口で止まった時点（付録B ⑨）で初めて表示し、それまでの目標表示は「v1.0」

**リリースの前の確認**
- ガイドが、作り直す理由と、手放すもの・残るものを言葉で伝える（付録B ⑩）。［リリースする］［もう少し作る］
- **製品の名前**（決定・2026-10-31）：最初のリリース（v0.1）の確認で、製品の名前を入れる欄を出す（最大20文字。空のままなら「無題」）。以後の版はこの名前を引き継ぎ、出荷の画面・製品の一覧・リリースの条件の表示で「（名前） v1.0」のように使う。名前は各世界の設定画面で変えられる。製品の名前は、作者の名前（台本⑧）とは別

**リリース画面の様式**（決定・2026-11-02）：製品ページと出荷の画面（下の「リリースの画面」）の様式は、次の3つで決める
- **実在の画面を手本にする**：どの画面も、実在のサイト・アプリの画面を手本にして作る。手本のないオリジナルの画面は作らない（書類など、画面でないものを様式にすることもしない）。写すのは構成・情報の密度・用語・時代の質感だけで、実在のロゴ・商標・ブランド名・アイコン・固有の配色や文言は使わない（4.8 の「作風・構図・質感は忠実に、ロゴ等は使わない」と同じ決まり）
- **世代は到達段で決まる**：時代は、世界を進むことでは進まない（4.8）。リリース画面の世代は版の番号ではなく、その製品の世界をその周でどこまで進化させたか（見た目の段）で決まる。後の周で同じ世界を先の段まで進化させれば、その周のリリース画面は新しい世代になる
- **出荷した時点の様式で残す**：出荷済みの製品ページ・売上報告は、出荷した時点の世代のまま変えない。製品の一覧（リリースの記録）に並べると、その世界を進化させてきた変遷が見える

**製品ページ**（決定・2026-11-01）：リリースの流れは「リリースする → 製品ページ（お客さんが見るページ）が出る → お客さんが買う → 売上（下のリリースの画面）」。確認で［リリースする］を押すと、まず製品ページが画面いっぱいに開く
- 見本と世代：ソフトウェアは3世代。第1世代（デスクトップ段の前半）＝昔のフリーソフト紹介サイト／ソフトウェアの保管庫サイトの詳細ページ風で、見本は v0.1＝`05-1-store-freeware.html`（「ソフト広場」）、v1.0＝`05-2-store-archive.html`（「ソフトウェア書庫」）。第2世代（段の中盤）＝2010年代のダウンロードストア風。第3世代（段の後半）＝今のストアページ風。第2・第3世代の様式は段階7の画面修正で先に作り、見本は次の区間で追加する。サイト名・ロゴは架空
- ほかの媒体の製品ページ：配信の版は動画・配信プラットフォームの作品ページ風、ウェブの版は自分のサイトに作る製品のストアページ、ゲームの世界の版はゲームストア風。いずれも、その世界の段に合わせた世代にする
- 中身：製品名・版・作者・紹介文（作ったものから組み立てる）・**プレイヤーが選んだスクリーンショット**（v0.1 は2枚、v1.0 は1枚の大きな写真＋一覧。撮っていなければ、その時点の画面を同じ部品で縮小して描く）・お客さんのレビュー（フィードバックをくれた利用者と、ほかのお客さん。よい声だけでなく、次の版のヒントになる声も混ぜる）・ダウンロード数や購入数
- 写真を選ぶ：確認の画面で、撮ったスクリーンショットから載せるものを選ぶ（未選択なら新しい順）。写真の出来が売上に少し効く（最大 +10%）。評価は**写っている中身（部品の数と種類）だけ**で見、配置の整い具合は効かせない（1.2-10）。個性的な画面でも損をしない
- 購入数が数え上がる短い演出（約3秒）の後、［売上を見る］で下のリリースの画面へ進む
- スクリーンショットを撮る理由（決定）：①進み具合のアルバム ②製品ページに載せる

**リリースの画面**（見本：付録D `04-release.html`。中身の構成の見本として使い、様式は下の世代の指定が優先）
- 余白社の「出荷」の画面。様式は製品ページと同じく上の「リリース画面の様式」で決める。ソフトウェアは3世代。第1世代（デスクトップ段の前半）＝2000年代のレジサービスの作者向け売上レポート風（表組みのWeb管理画面）。第2世代（段の中盤）＝2010年代のオンライン売上報告風。第3世代（段の後半）＝今のパートナー向け販売管理画面風。第2・第3世代の様式は段階7の画面修正で先に作り、見本は次の区間で追加する
- 中身の構成は世代共通：左に出荷した製品（作った画面を同じ部品で縮小して描く、名前・版・作者・作ったもの・**完成したセットの数**）、中央に売上、右に性能の一覧。朱色（#c8553d）は全世代で差し色として使う
- 売上は7日分の棒が1日目から順に伸び、合計のドルが数え上がる（約8秒）。日ごとの売上は合計を初日が最も多く、少しずつ減るように割り振る
- 中央の下にガイドの言葉（付録B ⑪）
- 続けて「性能」の一覧（スペック7項目）：いまの段階 → 次の段階、値段、効き目の1行。買える項目のみ押せる。1回目（v0.1）は色深度だけが強調される
- **次の版のテーマ**（決定・2026-10-31）：「次のバージョンを作り始める」の上に、次の版で目指すことを1行だけ出す。利用者の声から榎本が提案する形にし、どの世界にも「誰が、なぜ求めたか」という理由を付ける。見せるのは次の1つだけ

| 出荷した版 | 出荷の画面に出す1行 | もとになった利用者の声（榎本が伝える） |
|---|---|---|
| v0.1 | 次の版　v1.0：デスクトップとして使える画面にする | 「ほかのアプリも一緒に使いたい」（台本⑫） |
| v1.0 | 次の版　v2.0：配信に使える画面にする | 「この画面で配信したい」 |
| v2.0 | 次の版　v3.0：ウェブに出せる画面にする | 「配信を見られなかった人にも届けたい」 |
| v3.0 | 次の版　v4.0：映像を作れる画面にする | 「サイトに載せる映像も作りたい」 |
| v4.0 | 次の版　v5.0：ゲームを作れる画面にする | 「この画面で遊べるものを作りたい」 |
（v1.0 以降の声の文面は仮。世界4〜7を詰めるときに決める）

- 「次のバージョンを作り始める」で、画面が消えて真っ白になり、素の画面が新しいスペックで始まる（v1：256色の色、目標「v1.0 リリースまで 0/5」）
- 製品の「作者」の欄には、入力欄で答えた名前。答えていなければ作者の欄そのものを出さない

**リセットの範囲**
- 失う：ピクセル、作ったもの（部品・アプリ・機能）、自動カーソル、持ち場、世界の進み具合、窓の状態、要望の届いているもの
- 残る：ドル、スペック、トークン、スキルツリー、**購入済みのエディタの段**（段が上がっている場合、世界1はその段のエディタを作る内容になる）、**旧バージョンのセット書類**（前周の完成セットはファイルに記録として残る）、エクスポートの記録、スクリーンショット、自分で作った壁紙・テーマの設定、ガイドとのやりとりの履歴、プレイヤーの名前、製品の一覧（リリースの記録）
- **周回で作り直すもの（決定・2026-11-02）**：作ったセットは、その周のバージョンのものとして毎周作り直す。前周のセットはファイルに「旧バージョンの書類」として残って見られる（記録・コレクションとしての価値）。必須セットの完成は毎周の条件だが、2周目以降は段が上がっているため制作の中身が進化し、同作業の繰り返しにはならない。エディタのカスタマイズ（色など）は、段が変わったら配置はその段の標準に戻るが、色の選択は持ち越す（スキルツリー「構成を引き継ぐ」を取っている場合に、初めから有効になる）

### 4.7 長く遊べる仕組み（決定・2026-10-31）
インクリメンタルゲームとして長く興味を持たせるための10の仕組み。数値は付録C 10.5（仮値）。

**(1) 実績（マイルストーン）**
- この区間で約25個。1つ取るごとに全生成 +1%（足し算で重なる）。Steam版の実績と同じ一覧にする（10.3 の窓口から通知）
- 例：最初の1ピクセル／セーブ／オートカーソル10台・50台／Tessera を作る／最初のエクスポート／**パーツを初めて作る／セットを初めて完成させる／必須セットを完成させる**／部品をすべて置く／**ずれ直し10回**／ペイントソフトを乗り換える／大型アップデート／製品に名前を付ける／試作版 v0.1 を出す／v1.0 を出す／最初のスクリーンショット／スクリーンショット50枚／フィードバック10件・50件／ジョブを満員にする／アプリを7つ／壁紙を変える／ターミナルで自動化／応答なしを10回直す／隠し要素3つ（それぞれ1つ）
- 取ったときの知らせはその世界の形で：素の画面＝本文に1行、工房＝下の情報の帯、デスクトップ＝右下の通知「実績：〇〇」
- 一覧は各世界の設定画面の「記録」に並べる（取った日時つき。まだ取っていないものは名前だけ。隠し要素は「？？？」）
- 実績とボーナスはリリースしても残る

**(2) 前の世界の成果が、後の世界でも効き続ける**
- デスクトップのジョブの生成に、前の世界の積み上げ倍率を掛ける：**作ったパーツ1つごとに +0.5%**（50個まで）、素の画面のオートカーソル1台ごとに +0.1%
- 効き目の表示（4.1）と、タスクマネージャー（7）に「前の世界の積み上げ ×1.18」のように出す
- 世界4以降も同じ考え方で、直前の世界の成果を倍率にする（例：スクリーンショットの枚数→配信）

**(3) 手でやったことは、いずれ必ず任せられる**
- どの手作業にも、自動化の手段を用意する決まり。この区間の対応：

| 手作業 | 任せる手段 |
|---|---|
| 生成ボタンを押す | オートカーソル、押しっぱなしで連打（プラグイン） |
| 部品を作る | ジョブ「エディタ」（カーソルが工程を進め、工程ピクセルを生む。完成した部品は人の手で仕上げる） |
| エクスポート | ターミナルの命令「作り上げたものをエクスポート」 |
| スクリーンショット | 時計のタイマー、ターミナル |
| フィードバックに応える | 定型のフィードバックに自動で応える（設定アプリ2周目帯） |
| ずれ直し | 寸法線とスナップ（プラグイン2周目帯） |

**(4) 受託案件（しばりのある周回）**
- v1.0 を出した後の出荷の画面から、余白社の「受託案件」を1つ選べる（選ばなくてもよい）。次の版の間だけ、しばりがかかる。案件は、版の途中の決まった地点で達成になり、その場で報酬が入る
- 報酬：永続で全生成 +5%（1件ごと）と、その案件だけの壁紙またはテーマ
- この区間で用意する案件（2件）：「オートカーソルなしで Tessera を作る」（素の画面でオートカーソルを買えない。Tessera を作った時点で達成）、「16色のまま Tessera を作る」（カラーを作らない。案件中は素の画面の一覧からカラーが消え、セーブの次がフォントになる。カラーで増えるものは出ない（配色の選択・取り残されたピクセルなど）。同じく Tessera を作った時点で達成。2026-11-01 決定）
- 進行中の案件は、目標の行の下に1行で出す。途中でやめることもできる（報酬なし）
- セーブに「案件中かどうか」を持たせる。案件の中身は、あとから表に足すだけで増やせる作りにする

**(5) 推定時間（決定：ユーザー案）**
- ピクセルが足りない買い物と目標には、買えるまでの推定時間を出す：「推定 12分」「推定 1時間20分」（1分未満は「推定 40秒」）。いまの毎秒の生成量（手で押す分は含めない）から計算する
- **推定時間が短くなった瞬間を見せる**：何かを作って推定時間が1割以上短くなったら、約2秒だけ「推定 60分 → 30分」と前の値に取り消し線を引いて並べ、新しい値に置き換わる。目の前の待ち時間が縮むこと自体を気持ちよさにする
- 出す場所：見えているアップグレード、工房の出口のカード、デスクトップの「アップグレード」、リリースの条件のうちピクセルが要るもの
- 99時間を超えるときと、毎秒が0のときは出さない。数字のちらつきを防ぐため、10分を超える値は1分単位、1時間を超える値は10分単位で丸める

**(6) まとめ買い**
- オートカーソルとジョブのカーソルに、「×1」「×10」「買えるだけ」の切り替えを付ける（オートカーソルが10台を超えたら現れる）。値段と効き目と推定時間は、選んだ数のぶんで出す

**(7) タスクマネージャー**
- デスクトップのアプリ（ジョブの後、150万ピクセル）。Windows のタスクマネージャーに忠実に寄せる
- 「プロセス」の一覧：ピクセルを生んでいるもの（素の画面のオートカーソル・完成した部品・各ジョブ、スクリーンショットは直近10分の平均として小さい源）ごとに、毎秒の量と割合。掛かっている倍率（実績、前の世界の積み上げ、色深度など）も内訳で見られる
- 「パフォーマンス」：スペック7項目のいまの段階を、性能の画面らしい見た目で出す（見るだけ）

**(8) 世界ごとに、ときどき起きる出来事**
- いずれも、放っておいても損はしない（義務にしない）。同時に1つまで
- 素の画面「取り残されたピクセル」：カラーを作った後、2〜4分に1回、ページのどこかに色の付いた1ドットが現れる（30秒で消える）。押すと毎秒生成の20秒分
- **デスクトップ「ずれ直し」**：3〜6分に1回、組んだアプリの部品の1つが6〜14px ずれ、少し傾く。つまんで元の位置に戻す（吸い付き範囲8px）と、毎秒生成の30秒分のピクセル
- デスクトップ「応答なし」：3〜6分に1回、開いている窓の1つのタイトルに「（応答なし）」が付き、中身が白っぽくかすむ。閉じる→開き直す、または窓の「再起動」で、毎秒生成の60秒分。その窓のジョブは止まらない

### 4.8 見た目の進化の段（決定・2026-10-31）
**画面の変化を常に楽しませることが最大の売り**（1.1）。どの世界も、古い姿から最新の姿まで段を重ねて進化する。段ごとに**配置・大きさ・色・素材のどれかがはっきり変わる**ようにし、細部だけの違いの段は作らない。段はスキルツリーで手に入る。

- **名前の変化**：手本にするアプリが変わる大きな節目では、ソフトの名前も変わる。スキルツリーの項目は「ペイントソフトを〇〇に乗り換える」。同じ名前の中の古い版→新しい版は「〇〇をアップデートする」。デスクトップ（OS）はプレイヤーが付けた製品名なので名前は変えず、「大型アップデート」と呼ぶ

- **前の段に戻す**：設定で、手に入れた段のどれにでも見た目を戻せる（見た目だけ。機能は変わらない）
- **機能は引き継ぐ**：段が変わっても、持っている道具・パーツ・設定・作ったものは同じ。配置と見た目だけが変わる
- **マスの細かさ**は段ではなく解像度のスペック（3.4）で決まる
- **動作環境**（決定・2026-10-31）：画面の時代がちぐはぐにならないよう、エディタの段には、本物のソフトと同じ「動作環境」を付ける。手に入れたデスクトップの段（スキルツリーなので周回をまたいで残る）が足りないと、スキルツリーの項目は押せず「動作環境：デスクトップの大型アップデート2回目以降（いまは1回目）」のように出す（表示要件の壁と同じ見せ方。v1.0 の素の画面〜工房の間は、手に入れた段で判定する）。①② どれでも／③ 段2以降／④ 段3以降／⑤ 段5以降

### 4.9 アプリを作って入れる（決定・2026-11-01）
デスクトップの基本アプリ（ファイル・メール・写真・ごみ箱・時計・テーマ・ターミナル・タスクマネージャー）は、買って入れて終わりではなく、自分で組み立てて入れる。「UIを作る」というコンセプトをデスクトップでも続けるため。見本：付録D `03-6-app-build.html`

**流れ**
- アプリのひな型は、対応するUIセットを購入すると手に入る（〇〇.app という書類）。エディタ（Tessera／Gesso の「組む」）でその書類を開き、自分で作ったパーツをアプリの窓に置いて組み立て、［デスクトップに入れる］で使えるようになる
- **置いたパーツで機能が働く**：アプリごとに使えるパーツと、置くと働く機能が決まっている（例：ファイル＝一覧で中身が見える／戻るボタンで前の場所へ／並べ替えのボタンで並べ替え／検索欄で名前で探す）。今の「小さな機能」は、ピクセルで買う代わりに、そのパーツを作って置くことで手に入る（値段はパーツを作る費用へ移す）
- アプリに必要な新しいパーツ（検索欄・スイッチ・スライダー・本文の欄 など）は、エディタのパーツとして作る。ほかの場所から流用するときも、そのまま使い回さず、そのアプリに合う形に作り変える（例：テーマの明暗のスイッチ、写真の明るさのスライダーは、それぞれの役目に合う見た目と動きにする）。新しいアプリが新しいパーツを作る理由になる
- **デザインも自由**：配置、大きさ、色（選べる色の数は色深度のスペックに従う）、文字の大きさ、行の高さ、しま模様などを自分で決める。素材の見た目（窓の枠・ボタンの立体やガラス）はデスクトップの時代の段に従う
- ［おすすめの配置］で、標準の形に一度で組める（デザインが苦手な人のため。いつでも押せる。お手本の考え方で、従わなくても損はない。1.2-10）
- **写っている部品だけを数える**（決定・2026-11-02）：スクリーンショットは、写っている部品の数と種類で稼ぎを決める。配置の整い具合（重なりなし・端や半分にそろう）は損得に関係させない（1.2-10。旧仕様の「整った配置は撮影の配置ボーナスに効く」は廃止）
- 部品の枠（配置の目安の線）は組み立て中だけ見せる。入れた後のアプリには出さず、本物のアプリと同じ見た目にする（2026-11-01 決定）

**後から変えられる**（決定）
- 入れた後も、いつでも〇〇.app を開いて組み直せる。直した内容は［デスクトップに入れる］を押した時点で反映する（編集中も、入っているアプリとジョブは今の形のまま動き続ける）
- 元に戻す／やり直す、［おすすめの配置］、前に入れた形に戻す、を用意する

**詰みと不具合の防止**（決定。実装とテストで必ず確かめる）
- 置ける場所：パーツは窓の内側だけ、格子にそろえて置く。重なる位置には置けない（赤い枠で示し、手を離すと元の位置に戻る）。窓の外へ出せない
- 大きさ：パーツごとに最小の大きさがある（文字が入る幅を、表示中の言語で測って決める。英語・試験用の言語でもはみ出さない）
- 窓の大きさを変えたとき、デスクトップの段（画面の大きさ）が変わったときは、配置を比率で置き直し、入らなければ最小の大きさまで縮める。それでも入らないときは窓の最小の大きさを広げる。パーツが見えなくなる状態を作らない
- 読みやすさ：文字と背景の色の差が小さすぎる組み合わせは選べない（または文字の色を自動で読める色にする）。背景と同じ色で見えないボタンを作れない
- 消せない部分：窓の枠・タイトル・閉じる／最小化／最大化は、アプリの外枠なので外せない。どんな配置でも、窓を閉じる・動かす・最大化できる
- 必要な機能を外したとき：フィードバックや v1.0 の条件に必要な機能（例：並べ替え）のパーツを外した場合、依頼や条件の表示で「並べ替えのボタンを置くと直せます」と案内し、［おすすめの配置］に戻せばいつでも直せる。条件は「機能が使えること」で判定し、特定の配置は求めない
- 保存：配置のデータは読み込み時に検査し、壊れていたらそのアプリだけ［おすすめの配置］に戻して続行する（ほかのデータは失わない）
- 古いセーブ：すでにアプリと小さな機能を買ってあるデータは、買ってある機能のパーツを含む［おすすめの配置］で自動的に組み上がった状態にする（失うもの・追加の支払いなし）
- スクリーンショット・製品ページ・ジョブのカーソルの動き・応答なしの表示は、組んだ配置のとおりに描く

## 5. 画面仕様

### 5.1 共通
- 1920×1080 で設計した画面を、ブラウザの大きさに合わせて**等倍率で縮小・拡大**して中央に表示する（縦横比は保つ）。余白はその世界の背景色で塗る
- 書体・色・寸法は付録F に従う（デスクトップは Segoe UI → BIZ UDPGothic、最初の工房は DotGothic16。数字だけ等幅の書体にしない）。世界1の開始時だけ明朝体（Times New Roman / Noto Serif JP）
- 文字の最小サイズ 12.5px（1920×1080 換算）。本文 14px 前後
- 強調色はエディタで選んだ色（初期は #0067c0）
- 窓の右上の記号は、最小化（横線）・最大化（四角）・閉じる（×）を右端に。左上に色付きの丸を並べない。**並び順・左右の位置はプレイヤーが共通部品の制作で決めたとおりにする**（4.2）
- 押せる部品には必ず押したときの反応（押し込み、色の変化、開く、閉じる）がある

## 8. 時間の設計
- 目標：チュートリアル（v0.1 まで）約50分、v1 約5.5時間（受け入れは5〜7時間）。発売範囲（世界5まで）の本編は v2 約6時間・v3 約7時間と合わせて約19〜20時間、やり込み込みで全体20〜25時間。世界6・7は発売後の追加
- **アクティブ**：素の画面のクリック、部品の制作（工程）、要望メール
- **放置（開いたまま）**：自動カーソル・完成した部品とツール・持ち場は100%進む
- **不在（閉じている・タブが裏）**：放置の生成は100%で進むが、ストレージの時間（2〜24時間）まで。画面を撮る・ずれ直しは進まない。要望は上限まで溜まる。時計のタイマーとターミナルの自動化は不在中も動く（不在の上限内）
- 戻ったとき：その世界らしい形で1回だけ知らせる（素の画面＝本文の1行、工房＝コメント、デスクトップ＝通知「留守の間に 3時間12分ぶん作業しました（+128万）」）

## 9. データと例外
- **セーブ**：自動保存（10秒ごと、作る・書き出す・リリースなどの直後、画面を離れるとき）。保存先は10.3の「窓口」が決める（ブラウザ版＝ブラウザの保存領域、Steam版＝ファイル＋Steamのクラウドセーブ）。素の画面で「保存」を作るまでは保存しない
- **形式**：版番号つきの1つのデータ。版が上がったら読み込み時に変換する。読み込めない・壊れているときは、前回正常に読めたデータ（予備に1世代保存）に戻し、それもだめなら新しく始める前に確認を出す
- **書き出し・読み込み**：各世界の設定画面（このページの設定／拡張機能／設定アプリ）の最下部に「データ」の欄。ファイルとして書き出す、ファイルから読み込む、最初からやり直す（2回確認）
- **リリース**：リリースの直前に自動で保存し、リセット後にもう一度保存する。リリースの途中で閉じられたら、再開時はリリースの画面から
- **タブ復帰**：前回の時刻との差で不在を計算する（裏のタブで処理が止まっても正しく進む）。時計を戻した（差が負）ときは0として扱う
- **画面サイズ変更**：5.1 の等倍率表示を即座にやり直す。縦長や 1280×720 未満では「この画面は横長の広い画面向けです」と1行出し、そのまま縮小表示する
- **複数タブ**：同じゲームを2つ開いたら、後から開いた方に「別のタブで開いています」と出して操作を止める（Steam版は二重起動しない）

### 10.3 Steam版を見据えた作り（決定・2026-10-30）
将来 Steam で出す。**ブラウザの技術のまま作り、Steam版は Electron（ブラウザごとアプリにして配る仕組み）で包んで出す**。今回の区間ではSteam版そのものは作らないが、後から包めるように最初から次の形にする。
- **窓口（プラットフォーム層）**：セーブの読み書き、設定、データの書き出し・読み込み、実績、全画面の切り替え、終了を、`game/src/platform/` の1つの窓口にまとめる。ゲームの他の部分はブラウザやSteamを直接さわらない
- いまはブラウザ版の窓口だけ作る（保存＝ブラウザの保存領域、書き出し＝ファイルのダウンロード、実績＝何もしない）
- 後で Steam 版の窓口（保存＝ファイル＋Steamのクラウドセーブ、実績＝Steamの実績）を足すだけで済むようにする
- **実績の呼び出し口**：「エディタを作った」「最初のリリース」など、実績にできそうな出来事を窓口に知らせる（今は何もしない）。実績の一覧は未決定
- **ブラウザだけの機能に頼らない**：URLの後ろの指定（`?debug=1` など）は開発用だけ。ゲームの進行に必要な情報をURLやブラウザの戻る・進むに持たせない
- **画面の大きさ**：ウィンドウの大きさを変えても、全画面でも、5.1 の等倍率表示で崩れない（Steam版はウィンドウ表示と全画面の両方）

- **時間**：不在の計算は端末の時計の差で行う（9章）。時計を戻したときは0として扱う（すでに9章のとおり）

### 10.4 多言語対応（決定・2026-10-30）
世界に向けて出すため、**最初から多言語に対応できる作り**にする。基準の言語は日本語（仕様書・見本・台本は日本語で書かれている）。

**この区間で作るもの**
- 言語を切り替える仕組みと、**日本語（完全）・英語（下訳）**の2言語
- 英語は実装時に下訳を入れてよい（後で人の手で直す前提。下訳であることを翻訳ファイルの冒頭に書く）

**後から足す言語（ファイルを足すだけで済むようにする）**
- 目安：簡体字中国語、繁体字中国語、韓国語、スペイン語（スペイン・中南米）、ポルトガル語（ブラジル）、フランス語、ドイツ語、ロシア語
- アラビア語など右から左に書く言語は、画面全体を左右反転する必要があり手間が大きいので後回し。ただし妨げないよう、配置は「左・右」ではなく「行の始まり・終わり」で指定しておく（CSSの論理プロパティ）

**作りの決まり**
- **画面の文字をコードに直接書かない**。すべて言語ごとのファイル（`game/src/content/locales/ja.json` など）から読む。ガイドのセリフ・要望メール・アプリ名・ファイル名・部品名・スキルツリーの項目もすべて含む
- 文の中に数や名前が入るときは、文全体を1つの文として訳せるようにする（「{name}さん」「{count} 個の項目」のような差し込み）。単語をつなぎ合わせて文を作らない。数による言い方の違い（英語の 1 item / 2 items など）に対応する
- **数・日時・時刻の表示は言語ごと**（3.3、ファイルの更新日時、時計、カレンダー）
- **長さが変わっても崩れない**：英語・ドイツ語は日本語より長くなる。幅を文字に合わせて伸ばす、2行に折り返す、どうしても収まらないところは省略記号と、マウスを重ねたときの全文表示。確認用に、全文を約1.4倍に伸ばした「試験用の言語」を `?debug=1` から選べるようにし、はみ出しがないか確かめる
- **書体は言語ごと**：日本語＝付録F のとおり。中国語・韓国語は、同じ雰囲気の配布してよい書体を同梱する（例：Noto Sans SC／TC／KR）。最初の工房のドット書体は、言語ごとに配布してよいドット書体を選ぶ（候補：Fusion Pixel Font（中・日・韓）など）。ラテン文字・キリル文字が書体に含まれているかも確かめる
- **固有名詞の扱い**：人名（榎本 湊、水野 ひかり など）、社名（余白社）、アプリ名（エディタ）は、言語ごとに訳し方を決める用語集 `game/src/content/locales/glossary.md` を作り、意味の説明（例：余白社＝デザインの「余白」から）を添える。翻訳者が意味を汲んで訳せるようにする
- **絵の中に文字を入れない**（壁紙・ドット絵）。文字はすべて画面の部品として描く

- **言語の選び方**：最初はブラウザ（Steam版は Steam）の言語に合わせ、なければ英語。各世界の設定画面（このページの設定／拡張機能／設定アプリ）で切り替えられる。切り替えはその場で反映し、保存する
- **素の画面の言語の選択欄**（決定・2026-10-30）：素の画面の設定ページは2周目まで開けないため、素の画面の一番下に、素朴なHTMLの言語の選択欄を最初から置く（素の画面の見た目のまま）。言語の名前は、その言語自身の書き方で並べる（English、日本語、한국어 など。いまの表示言語に訳さない）。読めない言語で始まっても、自分の言語を見つけられるようにするため
- 見本（`docs/mockups/`）は日本語の手本。他の言語でも、構図・密度・文字の大きさの考え方は同じにする

### 12.3 不採用（理由つき。同じ案を戻さない）
| 案 | 理由 |
|---|---|
| 物理ディスプレイ・モニターの枠・机・部屋へカメラが出る演出 | 画面の中で完結することが大元の狙い |
| 進化する画面を小さな枠に展示し、別枠のゲームUIで操作する | 画面全体をゲーム世界にしたい |
| 特定OSの識別要素（三色ボタン、ロゴ） | 特定OSの模倣に見える |
| 全編白基調で色調も印象も変わらない画面 | 世界の違いとわくわく感が出ない |
| 元ゲーム後半の回路・3D空間の方向 | ユーザーが気に入らなかった |
| ボタンや文字が多すぎる画面 | 大事な部分と飾りの区別がつかない |
| 仮想マシンを単独の世界にする | 管理画面寄りになる（後半の自動化の機能として使う余地は残す） |
| 原点に戻る終わり方 | ユーザーが不採用 |
| 販売元の名前「小窓社」 | ユーザーが別案（余白社）を選んだ |
| **下絵をなぞってアイコンを描く仕組み（旧・世界2の中心）** | 「時計を描く」ような課題のなぞりでは自作感が弱い（2026-11-02 ユーザー判断）。お手本は足場として用意するが、なぞること自体を遊びの中心にしない |
| **整った配置へのボーナス（旧・撮影の配置ボーナス等）** | お手本を示すこと自体は速度と気持ちよさのために許容するが（2026-11-03）、整い具合を加点して従順さを評価にはしない。評価は中身だけにする |
