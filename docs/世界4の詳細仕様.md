# 世界4 配信 詳細仕様（案）

`docs/spec.md` §4.10 の骨格を詳細化する作業文書（2026-11-03・Muse作成）。
既に決まっていることは、この文書で初めて出す案はと書き分ける。はユーザーの承認をもってになり、その時点で `docs/spec.md` と `docs/経済の仮値.md` へ反映する。
世界4は**今回は仕様だけ**を作る。実装しない（実装の段階分割案は §12 に参考として置く）。

関連する既存の決定・資料：

- 骨格は spec §4.10、方向は `docs/世界4-7の案.md` の世界4
- 世界4の必須セット（4パーツ）は段階8bで仮置き実装済み（`docs/実装メモ.md`「世界4の未規定部分の仮決め」）。本書 §3 でその確定案を出す
- 画面様式の3つの決まり（すべての画面に実在のモデル／世代は到達段で決まる／出荷した画面はその世代で固定）は spec §4.6で、世界4にもそのまま適用する

---

## 1. 世界4の位置づけ

- 入口：世界3の「作れるもの」に並ぶ**配信ソフト**。表示要件はリフレッシュレート **60Hz**（1周目はここが壁になり、v1.0 をリリースして売上（＝ドル）で 60Hz を買ってから v2 で入る）
- 中身：プレイヤー自身のデスクトップと、世界3で作ったアプリ・写真が配信の素材になる。「作ったものが、いま操作している画面そのものを変える」の配信版として、**自分の作った画面を他人（視聴者）に見せる**初めての世界
- 出口：ウェブ（表示要件は通信速度「高」）。v2.0 リリースで売上（＝ドル）が入り、通信速度などを買って v3 へ
- 目安時間：v2 全体で約6時間（spec §2.3）。そのうち世界4そのものに割く目安は§11
- 次の世界に残るもの：**録画**（世界5のサイトに埋め込める素材）

## 2. 核ループ

場面を組む → 生放送 → コメントに合わせて場面を切り替える → 録画が残り、不在中も再生で稼ぐ → 構成を見直す。

1回の放送の流れを次のとおり固定する。

1. **準備**：場面（シーン）を2〜6個まで組む（§5）。配信者アイコンとテロップを確認する
2. **配信開始**：［配信をはじめる］を押す。放送は実時間で進み、標準の長さは5〜10分（§11 仮値）。いつでも［配信を終わる］で終えられる（短すぎる放送は録画の評価が低い、という形でだけ効かせる。失敗やペナルティは置かない）
3. **放送中**：コメントが流れ、視聴者数が上下する。プレイヤーの主な操作は**場面の切替**と、コメントの要望への応答（場面で応える／テロップで返す）
4. **終了**：放送が**録画**として1本残り、盛り上がりの頂点から**切り抜き**が自動で1本作られる（§8）。配信結果の画面（視聴の推移・コメントの内訳・得たもの）が出る
5. **不在中**：録画と切り抜きが再生され続けてピクセルが入る（オフライン計算に乗る）。戻ると「不在の間の再生」がまとめて表示される

自動化の決まり（spec §4.7「手でやったことは、いずれ必ず任せられる」）の世界4版：場面の自動切替（コメントの要望タグに合う場面へ自動で切り替える任せ方）を終盤の段で解放する。ただし自動切替は「最適な即応」より少し遅れ、手で切り替える方がわずかに良い——手でやる意味を残す。

## 3. 部品（パーツ）とセット

### 3.1 必須セット（8b仮置きの確定案）

段階8bで仮置きした4パーツを、そのまま必須セットとして確定する案。名前・役割は実装済みのものと一致させる（世界3で作り、ファイルに格納することが世界4へ進む条件の1つ）。

| パーツ | 役割 | 世界4での働き |
|---|---|---|
| 配信のプレビュー | 映像の表示領域 | 素材（デスクトップ／アプリ／写真）が映る主画面。場面切替の結果がここに出る |
| ソースの選択 | 素材の一覧と切替 | 場面に何を映すかを選ぶ。選んだ素材がプレビューに載る |
| 場面の切り替え | 場面の帯（ボタン列） | 組んだ場面を並べ、放送中にワンクリックで切り替える |
| コメントの一覧 | 流れるコメント欄 | 視聴者のコメントが流れる。要望・称賛はここに出る |

- 価格は 8b 仮置きの 2,000,000 ピクセルを存置（世界3の規模感に対する値。最終調整は全機能後の調整パス）
- この4つが揃えば配信は成立する。以後の部品はすべて「配信を豊かにする」任意側

### 3.2 任意セット「演出セット」

世界3のエディタで作る任意セット（世界2→3の任意セットと同じ作り：買うと作れるようになり、作って初めて効く）。

| パーツ | 役割 |
|---|---|
| テロップ | 文字を映像の下部に流す・固定する。コメントへの返答と告知に使う（要望応答の手段が増える） |
| 映像の枠 | プレビューの周りの枠と背景。見た目の段とは別に、プレイヤーが選んだ装飾として映る |
| アイコンの表示 | 描いた配信者アイコンを映像の隅に置く（§7。無いうちは名前だけの表示） |
| 場面の予約 | 次の場面を予約しておき、コメントの合図で即座に切り替える（切替の遅れが減る） |

### 3.3 世界4の中で増える部品

世界4到達後の段（§9）で、配信ソフト自身の「作れるもの」として増える部品。作り方はエディタ（世界3の窓）に戻って作る形に統一する（制作の場所を増やさない）。

| パーツ | 解放 | 役割 |
|---|---|---|
| 切り抜きの棚 | 段3 | 切り抜きを並べて見せる置き場。録画より再生の単価が高い |
| 同時配信の枠 | 段4 | 2つ目のプレビュー。小さい窓で別のアプリを映し続けられる（場面の素材が厚くなる） |
| 番組表 | 段5 | 放送の予定を組む。時間になると自動で放送が始まる（不在中も放送が回る入口） |

## 4. 画面構成

実在モデルの決まり（spec §4.6）に従い、配信ソフトの画面は**実在の配信ソフト（OBS Studio 系）の画面骨格**をモデルにする：中央にプレビュー、下にソースと場面の帯、右にコメントと配信の制御、という配置・密度・用語の骨格だけを借りる。ロゴ・製品名・固有の配色や文言は使わない。

- 全画面が配信ソフトそのもの（世界3のデスクトップに戻る窓ではない）。ただしプレビューの中身は世界3のデスクトップそのものなので、「前の世界が次の世界の中で動く部品になる」が画面の中心で起きる
- 主な領域：プレビュー（中央・最大）／ソースの選択（左下）／場面の帯（下）／コメントの一覧（右）／配信の制御と視聴者数（右上）／配信者アイコン（プレビューの隅、部品がある場合）
- 作っていない部品の領域は置かない（さわれない飾りのUIを置かない決まり）。部品が増えると画面が組み上がっていく——世界1〜3と同じ「作るほど画面が育つ」見せ方を配信ソフトでも繰り返す
- 放送中でないときは「準備」の顔（場面を組む画面）、放送中はコメントと視聴者数が動き出す。同じ画面のまま空気が変わる
- 配信結果・録画の一覧は、動画・配信プラットフォームの**チャンネルページ／管理画面の骨格**をモデルにした別画面（§10 の製品ページ様式と揃える）

見本（HTML）は本書の承認後、段ごとに作る（世界を詰めるときに作る決まり。§9 の段ぶん）。

## 5. 場面（シーン）

- 場面は「映す素材1つ＋演出部品の組み合わせ」の保存単位。素材は：デスクトップ全体／アプリ1つの窓（作ったアプリから選ぶ）／写真（世界3のスクリーンショット）／録画の再生／アイコンとテロップだけの「休憩・告知」面
- 場面ごとに短い名前を付けられる（初期名は素材から自動）。場面の帯に並ぶ順番は入れ替えられる
- **場面の数の上限はメモリのスペックに効かせる**（`世界4-7の案.md` の未決定事項への回答案）：メモリの段に応じて 2 → 3 → 4 → 6。理由：場面数は放送中の判断の幅そのもので、上限がスペックで伸びる形は「性能が遊びに効く」の分かりやすい実例になる。メモリが足りないうちは帯に「場面はあと○個、メモリを上げると増えます」と表示要件の形で出す
- 放送中の切替：場面の帯をクリック（または数字キー）。切り替えると一瞬の暗転／スライドの演出が入る（段で増える）。同じ場面を長く映し続けると視聴者の新鮮味が下がり（§6）、切替直後はコメントが反応する

## 6. 放送中の仕組み

### 6.1 視聴者

- 同時視聴者数は、開始直後に少しずつ増え、場面とコメントの空気に反応して上下する。下限は常に1以上（ゼロになって詰む状態を作らない）
- 増減の要因は画面で追えるものだけにする：場面の新鮮味／コメントの要望への応答／盛り上がりの持続／（段4以降）おすすめへの掲載
- ピクセルは **同時視聴 × 秒** で入る（統一された毎秒モデル：放送中は「視聴」が毎秒の源）。数値は §11

### 6.2 コメント

- コメントは右の欄を下から上へ流れる（視聴者の見せ方は流れるコメント。世界5の「ページを動くカーソル」と分ける）
- 種類は5つに絞る：挨拶／感想（いまの場面への反応）／**要望**（「○○の画面が見たい」——場面の素材タグと対応）／**称賛**／**応援**。荒らし・悪意のあるコメントは置かない（このゲームの温度感に合わせ、判断は §13 の論点として残す）
- **要望に応える**：要望のタグに合う場面へ切り替える（またはテロップで返す）と、そのコメントが「ありがとう」の形に変わり、トークンが入る（トークンの出どころ：コメントの要望・称賛・常連の応援）
- 常連：同じ名前の視聴者が繰り返し現れる。応援（トークン）をくれるのは主に常連。名前とアイコン色は固定の数人を用意し、記録の画面で「常連」として数えられる
- 滑らかさ：コメントの流れと場面切替の滑らかさはリフレッシュレートで変わる（60Hz＝標準。120Hz 以上で流れが滑らかになり、毎秒に小さな倍率）。「スペックが画面に出る」の配信版

### 6.3 盛り上がり

- 放送ごとの「盛り上がり」を内部の値として持つ：要望応答・切替の反応・称賛で上がり、同じ場面の継続で下がる。視聴者数の増減と録画の評価（§8）に効く
- 画面には数字でなく、コメントの密度と視聴者数の動きで読ませる（管理画面にしない）。ただし配信結果の画面では内訳を数字で出す

## 7. 配信者アイコン

プレイヤーはドットで自分の配信者アイコンを描く。顔出しの代わりに、描いたアイコンが画面の隅でコメントに反応する。この「描く」は配信者としての表現として残る（世界2の制作とは別物）。

描く道具の細部：

- 16×16 のドット絵から始まり、段3で 32×32 に広がる。使える色の数は色深度のスペックに従う（世界共通の決まりの流用）
- 道具は最小限：鉛筆／消しゴム／塗りつぶし／色の吸い取り、元に戻す。グリッド表示つき。世界2の工房ほどの制作工程にはしない（ここは「表現」であって「制作」ではない、の線引き）
- 反応のさせ方：コメントの種類に応じてアイコンの横に吹き出しの記号（♪／！／ハートの記号など自作の記号）が出る、要望に応えると小さく跳ねる。表情差分の描き分けは要求しない（描いた1枚がそのまま使える）
- アイコンはチャンネルページ（§10）と世界5のサイトにも顔として出る

## 8. 録画と切り抜き

放送が終わると録画が残り、閉じている間も再生で稼ぐ。録画は世界5のサイトに埋め込める素材になる。

細部：

- 録画は放送1回につき1本。タイトルは日付と最も映していた場面から自動で付く（変えられる）。サムネイルは放送中に最も盛り上がった瞬間のプレビュー画像
- **切り抜き**は盛り上がりの頂点の前後から自動で1本。手で範囲を選ぶ操作は置かない（「手でやったことは任せられる」以前に、まず自動で足りる形にする。手動化は論点 §13）
- 再生の稼ぎ：録画と切り抜きは毎秒の源として再生数が積み上がる（不在中も）。単価は切り抜き＞録画で、新しいものほど高い（古い録画は少しずつ落ち着くがゼロにはしない）
- 置き場：世界3のファイルの中に「録画」の書類としても残る（作ったものの所在をファイルに寄せる既存の作法）。世界4のチャンネル画面からも一覧できる
- v2.0 の売上への効き：spec §4.7「直前の世界の成果を倍率にする」の配信版として、**録画の本数と総再生**が v2.0 の売上倍率になる（例として spec にある「スクリーンショットの枚数→配信」は v1.0 側の倍率の例）

## 9. 見た目の段（世界の中での進化）

段の方向：テスト配信（静止画＋コメント欄）→ 通常配信 → 演出つき → 番組構成（場面の複数持ち）→ 最新の配信スタジオ。どの世界も簡素な姿から始まり、最新の現代感の姿まで進化する。世代はバージョン番号ではなく**その世界で到達した段**で決まる（spec §4.6）。

段の定義（解放は世界4のスキルツリー帯とチャンネルの成長で進む）：

| 段 | 名前 | 姿とモデルの骨格 | 増えるもの |
|---|---|---|---|
| 1 | テスト配信 | 2010年代前半の個人配信ツール風。プレビューは写真（静止画）の差し替え＋コメント欄だけ | 場面2つ、コメント、録画 |
| 2 | 通常配信 | 配信ソフトの標準形。デスクトップとアプリがそのまま映る | 場面3つ（メモリ次第）、要望コメント、常連 |
| 3 | 演出つき | テロップ・枠が載り、切替に演出が入る | 演出セットが効く、アイコン32×32、切り抜きの棚 |
| 4 | 番組構成 | 複数の場面を番組として並べる形。同時配信の枠 | 同時配信の枠、おすすめ掲載の出来事（§10） |
| 5 | 配信スタジオ | 現代の配信スタジオ風（暗い背景に鮮やかな映像） | 番組表（自動放送）、場面の自動切替 |

- 段が上がるたびに画面の骨格が変わること（色だけの差し替えで済ませない）。サムネイルで段の違いが分かることが受け入れの物差し（世界3のリリース画面で学んだ基準）
- 配信の製品ページ（§10）の様式世代も、この段から決まる

## 10. チャンネル・出来事・v2.0 リリース

- **チャンネル**：配信者アイコン・名前・登録者数・録画と切り抜きの一覧を持つ画面。骨格は動画・配信プラットフォームのチャンネルページ。登録者数は視聴と応援で少しずつ増え、毎秒（録画の再生単価）と段の解放に効く「記録と倍率」の数として扱う（買うものではない）
- **出来事**：おすすめに載る（一定の視聴を超えた放送の後、しばらく流入が増える）／常連が増える／要望が殺到する回。いずれも「直すとお礼」型の困りごとは世界5に譲り、世界4の出来事は前向きなものに寄せる
- **v2.0 リリースの条件**：世界4の段3到達／録画を○本残す／世界5の入口（通信速度「高」）は売上（＝ドル）で買う側に置く（他の版と同じ形）。条件の表示は世界3の配信ソフトの表示要件と同じ作法で出す
- **製品ページ（v2.0）**：動画・配信プラットフォームの作品ページ風。世代は出荷時点の世界4の段で決まり、出荷後は固定。**出荷（売上報告）画面**はプラットフォームの収益・アナリティクスの骨格をモデルにする
- リリース時の声は「配信を見られなかった人にも届けたい」。これが世界5（ウェブ）の入口の動機になる

## 11. 数値の仮置き

数値はすべて仮で、`game/src/config/balance.ts` の1か所にまとめる前提（ repo の決まり）。最終調整は全機能が入った後の調整パスで行う。ここでは規模感だけを置く。

- v2 の目安は約6時間（spec §2.3）。内訳の目安：世界1〜3の作り直しと並行制作で約3.5時間、世界4で約2.5時間
- 放送1回の長さ：5〜10分。同時視聴の初期の上限は数十人規模から始まり、段と登録者で数千規模へ
- 毎秒の規模感：放送中の視聴（同時視聴×単価）が、その時点の世界3の毎秒を少し上回る程度から始める（新しい世界が少し強い、の既存バランスの考え方）。録画の再生は放送中の数分の一だが、不在中も積み上がる
- 必須セット価格 2,000,000 ピクセル（8b 仮置き）／演出セットはその数倍／世界4内の部品は段の解放と合わせて買う形
- `docs/経済の仮値.md` の v2 行（旧試算：約9時間）は第3版の配分（約6時間）と合っていない。本書の承認時に合わせて更新する

## 12. 実装の段階分割（参考・今回は実装しない）

実装に進むときの分割案。1段階＝Codex への1つの作業指示、の既存の作法に従う。

- **段階9a**：配信ソフトの基盤（必須4パーツの実働、場面、放送ループ、コメント、視聴、録画）。段1〜2。世界3からの入口と表示要件の判定を含む
- **段階9b**：演出セットと世界4内パーツ、アイコンのドット絵、切り抜き、チャンネルの成長と出来事。段3〜5
- **段階9c**：v2.0 リリース一式（条件、製品ページ、出荷画面、通信速度の購入と世界5の入口だけを開ける——世界5そのものは次の区間）
- 各段階に画面の見本（§4・§9）とスクリーンショットの必須セットを付ける（既存の決まり）

## 13. 未決定・判断が要る点（ユーザー判断待ち）

1. **場面の上限をメモリに効かせる案（§5）の採否**——効かせない場合は段で一律に増やす
2. **切り抜きは自動のみで足りるか**（§8）——手で範囲を選ぶ操作を足すかどうか
3. **荒らし・悪意コメントの有無**（§6.2）——置くなら「場面で応える以外の対処（無視・非表示）」という新しい操作が増える。置かないと温度感は保てるが、配信らしさは少し薄くなる
4. **登録者数を「買えない数」として扱う案（§10）の採否**——ピクセルで買える成長に寄せる選択肢もある
5. **放送の長さ**——5〜10分の実時間放送は、このゲームのテンポ（他世界は数十秒単位の手触り）に合うか。短い「3分放送」を標準にする案もある
6. **配信ソフト／チャンネルの固有名**——世界2のエディタに Tessera 等の画面上の呼び方があるのと同じく、配信ソフトにも固有名が要るか（spec §0.1 の対応表に足す件）
