# 段階8b：実装ドメインによる所要時間の診断

2026-11-03（日本時間）。仕様書第3版の3.3・4.2・4.3・4.6・4.7・11章、付録Cの操作時間の仮定をもとに計測した。部品制作の想定が90／135／180秒の場合、v0.1の出口まで約46／63／79分、v1開始からv1.0出荷完了まで約1時間41分／2時間06分／2時間33分となった。**中央ケースのv0.1は目標40〜60分を超え、v1は全ケースで目標5〜7時間を下回る。数値は調整していない。**

全統計と前提は [measurement-summary.json](measurement-summary.json) に保存した。これは操作ログを除いた要約で、元の全ログはGit管理外の `game/artifacts/stage8b/economy.json` に出力される。ブラウザ操作の実測ではなく、現行のゲーム処理に操作時間を与えた診断である。

## 再現

リポジトリ直下で実行する。`game/` の依存パッケージが必要。

```sh
node tools/measure_stage8b.mjs --out game/artifacts/stage8b/economy.json
```

中央ケースだけの実行：

```sh
node tools/measure_stage8b.mjs --part-seconds 135 --out game/artifacts/stage8b/economy-135.json
```

Vite SSRで実装のTypeScriptを読み、通常の `advanceActiveTime`、購入、4工程、組み立て・インストール、要望、撮影、出荷、スペック購入、周回を実行する。価格・毎秒・売上・条件・自動制作の計算式はツール側に複製していない。壁時計を `BALANCE.measurementStage8b.startAt` に固定し、時計の要望も同じ分境界で発生させる。出荷中はゲームの `elapsedMs` が停止するため、計測用の経過時間を別に積算する。

各フェーズの上限は24時間。未完走やエラーの場合は到達状態を結果に残す。今回の3ケースはすべて `status: complete`。同じ固定日時で135秒ケースを再実行し、全操作ログと統計を含むシナリオJSONの完全一致を確認した。

## 前提と購入方針

- 生成ボタンは毎秒2.5回。1パーツ90／135／180秒を4工程に均等配分し、判断4秒、ガイドの初読15秒とする。操作時間や購入方針の値は `BALANCE.measurementStage8b` に置く。
- 生成ボタンを押すのは購入待ちの間だけ。実際の `pressSeed` による勢いを含め、制作・案内読み・組み立て中には押さない。
- 世界3では制作・操作・購入・案内読みなどの能動区間と、同じ長さの放置区間を対にする。能動50%・放置50%となり、両方の区間でジョブとエディタ補助が進む。
- UIセットを購入し、実4工程を経て `app-edit` → `app-recommend` → `app-install` を行う。v1では本線22＋任意25の計47パーツ、エディタを含む9アプリ、10セットを作る。UIセットのひな型に加えて旧C5のアプリ・機能価格を重ねて払う経路は使わない。
- 次の建設を優先する。制作の合間は次の有料offerの残高を確保し、追加のカーソル・ジョブ・更新は実action前後の毎秒差から回収秒を求める。買える候補のうち、オートカーソル120秒以内、ジョブ600秒以内で最短回収のものを買う。持ち場はメモリ容量の範囲でエディタ・ファイル・写真・ターミナルの順に割り当てる。発売可能で次の版の必須スペックを買える売上になれば、追加投資を止める。
- 自動制作は通常の `advanceDesktopTime` 内で呼ぶ `advanceWorkshopAssistance` だけを使う。前三工程を準備できても、最後は人手の操作確認が必要。
- 要望は実際の制作・色変更・並べ替え・検索・壁紙・テーマ・予約・削除・お題の撮影で達成する。隠し要素、取り残されたピクセル、オフライン収入は使わず、撮影の連打で稼がない。
- ターミナルは未エクスポートのterminalセットを実コマンドで書き出し、実行後に止める。「応答なし」は実際の再起動で直すため、既存の毎秒60秒分の復帰報酬を含む。有料エディタプラグインと任意スペックは追加購入しない。

これは購入方針を明示した1つの自動プレイである。最速攻略、実際のプレイヤーの操作速度、すべての購入順序を代表する結果ではない。

## v1が目標を下回る内訳

目標は仕様書8章・11章の約5.5時間、受け入れ範囲5〜7時間。今回は1時間40分〜2時間33分で、全ケースが下限より短い。

世界3の能動・放置時間は処理中に実際の世界を見て積算した。次の世界1・2の時間は、v1の条件成立までの時間から世界3の両区間を引いた値である。

| 1パーツの手作業想定 | v1の世界1・2 | 世界3の能動操作 | 世界3の放置 | 製品ページ・出荷 |
| --- | ---: | ---: | ---: | ---: |
| 90秒 | 42分21.8秒 | 28分39.1秒 | 28分39.1秒 | 52秒 |
| 135秒 | 58分51.8秒 | 33分07.35秒 | 33分07.35秒 | 52秒 |
| 180秒 | 1時間15分21.8秒 | 38分08.7秒 | 38分08.7秒 | 52秒 |

新しい経済では、UIセットのひな型・材料を買い、作った材料からアプリを組み立てる。旧アプリや追加機能の大きな価格を重ねて払う待ち時間がなくなった。さらに、稼働している道具の数でジョブの土台が育ち、実エディタジョブが任意25パーツの前三工程75件を準備する。中央ケースの手動工程は113件（世界2の22×4＋世界3の25×仕上げ1）、自動工程は75件だった。これらの実装上の変更が同時に入るため、各要因だけで何分短くなったかという比較実験は行っていない。

中央ケースのv1の収入内訳は以下のとおり。端数は表示上丸めている。

| --- | ---: |
| 通常の毎秒生成 | 13,568,394,944 |

再起動報酬は総生成の約17%を占める。写真は約0.00000228%で、このプレイでは稼ぎの本線にならない。生成区分の合計との差は浮動小数点の丸めによる約0.001ピクセルである。

**本計測に合わせる価格・倍率・工程時間の変更は行っていない。** 時間目標を満たすための調整は、全機能がそろった後の専用工程に残す。
