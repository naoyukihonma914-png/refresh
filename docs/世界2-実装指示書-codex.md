# 世界2 実装指示書（はめる方式＋Aseprite骨格）— Codex向け・自己完結版

前提：`docs/world2-fitting-redesign` の文書PR（#28）がマージされた main を正本としてください。仕様の正は `docs/spec.md` §4.2・§4.4・§4.8・§5.3、`docs/デザインの決まり.md` §4、`docs/世界2-殻とピース対応表.md`（本指示書の末尾にも全文を添付）。この指示書と仕様が食い違う場合は仕様が優先です。

## 最重要の作業ルール
- 世界2（工房）の制作まわりと画面は**ゼロから作り直す**。既存の制作UI・4工程ロジックへの継ぎ接ぎで済ませない（基盤＝セーブ／プラットフォーム層／窓操作／数値の整形は流用可）
- ブランチ `codex/world2-fitting`、Draft PR 1本。下の小段階ごとにコミットし、都度短く報告
- 数値はすべて `game/src/config/balance.ts` の1か所へ（値は仮値。細かい調整はしない）
- 画面の文字はすべて locales（ja/en）へ。JSXに文字列を直接書かない（記号も同様、既存の建築テストに従う）
- 作業の最後に、指定のスクリーンショット一式を撮って報告に含める。各画面の最終形1枚はPRにも入れる

## 背景（なぜ作り直すか）
現行の制作は「パネルのボタンを押すと要素が自動で付く」4工程で、手ざわりがなく、パネルが複雑でした。新方式は、世界1で採用した「窪みにはめる」操作を世界2の制作そのものに拡張します。あわせて工房の見た目を、実物の Aseprite（古い版）の骨格と質感に寄せてゼロから作り直します（使っていた世代が懐かしさを感じる密度・質感が目標。ロゴ・既存アイコンそのものは使わず、アイコンは自作のドット絵）。

## 小段階 W2-1：制作方式（殻＋ピースをはめる）
1. **殻**：パーツを選ぶと、そのパーツの土台（殻）が行き先の窓の中に・実際の大きさで現れる。殻が居場所と大きさを決める。旧工程1「場所を決める」（ドラッグ配置・寸法決め）は廃止
2. **ピース**：パネルにはピースの一覧だけ（未出現／出現中／はめ済みの状態表示）。ピース名を押すと作業台の端（右下）に出現する。ドラッグして窪みの近くで離すと吸着し、音と軽い反応ではまる。はめたピースはその場で実働する。はめたピースは置き場（出現エリア）へドラッグで戻して外せる
3. **完成**：全ピースがはまった時点で完成（旧工程4「仕上げ」の関門は廃止）。完成演出（毎秒の値が合計へ飛ぶ）とコンボは既存の決定を維持
4. **ピース払い**：旧工程払いの総額を、そのパーツのピース数で割ってピース単価とする（均等割り）。`balance.ts` に持つ
5. **窪みの共有**：同寸ピースは窪みを共有する。窓の枠の最小化・最大化・閉じる（3つの窪みのどれにもはまる。機能はピースの記号に従う）、写真の前へ・次へ。状態ピース（メールの未読／既読、ターミナルの実行／停止）は1つの座に2ピースを重ね、切り替えで表が替わる
6. **スクロールバー**：窓の枠の右端の窪みに1ピース（溝・つまみ・矢印一体）としてはめる。枠を作ると対象の窓に実際に働くスクロールが付く（現行の FrameScrollPane の挙動を維持）
7. **パネル**：制作中のパネルに残すのは、ピース一覧＋「調整を開く」＋戻る＋同じセットのパーツのチップ列だけ。工程リスト・要素ボタン列・インスペクタ・寸法の数値欄・確認／試行ブロックは撤去。セット一覧→パーツ一覧のドリルダウンと「次はこれ」「短期目標」の常駐は維持
8. **調整（こだわり）**：色・丸み・文字の大きさ等は任意レイヤー。「調整を開く」でのみ出し、制作途中・完成後のどちらでも変更可。スポイトはこの中に出す。「おまかせ」（お手本の値の一括適用）は維持
9. **お手本**：窪みは部品の構造として常時表示。お手本OFFで消えるのは短期目標・次ピースの誘導などのヒントだけ。数字（ピース払い・毎秒）にお手本準拠の影響は一切なし
10. 全52パーツの殻・ピース・窪みは末尾の対応表どおり（プラグイン2・配信4も同じ文法で実装）

セーブ：schema 18 の維持を狙う。制作途中の状態は「はめ済みピースの集合」で表し、出現中ピースの位置が必要なら任意フィールドで足す。旧方式で制作途中だったパーツは、付いている要素をはめ済みピースとして読み替える移行を入れる

## 添付：世界2 全パーツ「殻・ピース」対応表（全文）

（以下、docs/世界2-殻とピース対応表.md と同一内容）
現行カタログ（`game/src/content/workshopCatalog.ts`）の全セット・全パーツと、その要素リストを土台に、「殻＋ピースをはめる」方式へ読み替えた対応表。対象は仕様上の46パーツ（共通〜タスクマネージャー）に、追加パーツ（プラグイン2）と配信セット（4、世界4用）を加えた全52パーツ。

## 共通ルール（ドラフト）

- **殻**：パーツを選ぶと、行き先の窓の中に実寸で現れる土台。殻自身がそのパーツの居場所と大きさを決める（旧・工程1「場所を決める」は廃止）。
- **ピース**：現行の「要素」がそのままピースになるのが原則。パネルでピース名を押すと作業台の端（右下のピース置き）に出現し、ドラッグして窪みへ。はめた瞬間にそのピースは実働する。全ピースがはまると完成。
- **窪み**：ピースの外形そのものの凹み。原則は専用の窪み1対1。ただし**同寸ピースは窪みを共有**し、どれにもはまる（機能はピースの記号・中身に従う）。共有する組は表で「共有」と明記。
- **例外的な統合**：窓の枠のスクロールバーは、現行の3要素（溝・つまみ・矢印）を1ピースに統合する（2026-11-03の一体化決定どおり）。
- **状態ピース**：未読／既読、実行／停止のように「2つの状態が1つの座を取り合う」ものは、2ピースを1つの座に重ねてはめ、切り替えで表に出る方が替わる形にする。
- **調整（こだわり）**：色・丸み・文字の大きさ等は、この表の対象外。現行のカスタマイズ項目をそのまま任意レイヤーへ移す。
- **工程払い**：旧工程払いの総額を、そのパーツのピース数で割ってピース単価とする（初回は均等割り。重み付けは数値調整時）。

## 数えた結果と気づき

- ピース数は1〜5個（大半は2〜3個）。現行の要素数とほぼ同じで、工程払いの総量は変えずに済む。
- 窪み共有（逆付けが面白い）になるのは今のところ2組だけ：窓の枠の最小化・最大化・閉じる／写真の前へ・次へ。他に同寸の組がほしければ部品側の設計で足せる（例：ファイルの並べ替えの順序ボタンを2つに分ける等）— 要検討。
- ピース1個のパーツ（基本ボタン）は「殻＋1ピース」の速いパーツとして残す案。物足りなければ、ボタンの「押し面」を殻から切り出して2ピース化する手もある — 要検討。
